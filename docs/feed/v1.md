# Feed v1: what `trading.feed` actually serves (T5.1)

Contract origin: `docs/loop/designs/T6.1.md` §4. Machine-readable schemas: `docs/feed/schema/v1/*.json`,
checked by `trading.feed.schema` (a small JSON Schema subset; `jsonschema` isn't installed) in
`tests/loop/test_feed.py`. Everything is **SIMULATED** and every envelope carries `simulated: true`.

Run it: `PYTHONPATH=src python -m trading.feed.serve --port 8765 [--data-root data/local]`. It binds
`127.0.0.1` (only loopback hosts are accepted), serves `GET` only (every other method gets 405 before routing),
reads `data/local` without writing to it, and imports no exchange client.

## 1. Endpoints

| Endpoint | Returns | Schema |
|---|---|---|
| `GET /v1/health` | feed status, component status from file freshness (with the evidence strings) | `health.json` |
| `GET /v1/runs` | REPLAY runs (`replay/<id>/`, `signals/once-replay/<id>.jsonl`) and LIVE_PAPER days, each labelled with its mode | `runs.json` |
| `GET /v1/runs/{id}/summary` | REPLAY: raw `summary.json` + `gate.json` (or `null`); LIVE_PAPER day: signal count | pass-through |
| `GET /v1/strategies?mode=LIVE_PAPER\|REPLAY[&run_id=]` | strategy rows for exactly one mode | `strategies.json` |
| `GET /v1/stream?mode=&run_id=[&topics=][&max_events=]` + `Last-Event-ID` | SSE | `envelope.json` + one per type |

Not built in T5.1 (they're in T6.1 §4.2): `/v1/ping`, `/v1/meta`, `/v1/snapshot`, `/v1/candles`, `/v1/signals`,
`/v1/positions`, `/v1/fills`, and cursor pagination on `/v1/strategies`.

## 2. Stream semantics

- One channel per `(mode, run_id)`. A LIVE_PAPER channel reads only `signals/<date>.jsonl` and `ticks/<date>/`;
  a REPLAY channel reads only `replay/<run_id>/` or `signals/once-replay/<run_id>.jsonl`. A `live-*` run_id on
  REPLAY, or a replay id on LIVE_PAPER, is a 400. The adapter also refuses any source record whose `mode` isn't
  the channel's, or that isn't `simulated: true` (counted in `heartbeat.refused_total`).
- **Replayable events** (`signal`, `paper_fill`, `position`, `strategy_status`, `data_quality`) get a strictly
  increasing `seq`, go into a bounded ring buffer (default 50 000), and are sent with SSE `id: <seq>`.
- **Control events** (`hello`, `heartbeat`, `quotes`, `resync`) are per connection. They aren't buffered, carry
  **no SSE id**, and repeat the last replayable `seq`. *Deviation from T6.1 ("seq strictly increasing"):* seq is
  strictly increasing over replayable events and non-decreasing over the whole stream. This keeps
  `Last-Event-ID` always pointing at a replayable event, so resume is exact.
- **Resume:** `Last-Event-ID` inside the buffer replays everything after it. If it's older than the buffer, the
  server sends `resync{buffer_expired}`; if it's ahead of this server's seq, it sends `resync{server_restart}`.
  After a resync the whole buffered backlog follows and the client must treat it as a snapshot. A connection
  without `Last-Event-ID` gets the whole buffered backlog (for a REPLAY run, that's the full run).
- REPLAY events are emitted in market-time order (`events.jsonl` is grouped by source), as fast as the client
  reads. There's no pacing (`hello.replay.speed = null`).
- Rates: `quotes` at most once per `--quotes-s` (≥ 1 s) and only when the book changed; `heartbeat` every
  `--heartbeat-s` (1 s); raw ticks are never sent. Overload: nothing queues per client beyond the ring buffer. A
  client that falls behind it gets `resync`, and the events it missed are counted in `heartbeat.dropped_total`.
- The FastAPI SSE layer adds a `: ping` comment after 15 s idle; `retry: 2000` is set on `hello`.
- Implicit LIVE_PAPER run (no `run_id`): at the UTC day rollover the stream sends `resync{run_changed}` and closes.

Events implemented: `hello`, `heartbeat`, `quotes`, `signal`, `paper_fill`, `position`, `strategy_status`,
`data_quality`, `resync`. **Not emitted yet:** `candle` (no candle source is wired up) and `scan_cycle` (the
scanner doesn't log cycles).

## 3. Schema reconciliation (all in `src/trading/feed/adapter.py`, nowhere else)

General rules: a field the source can't know is `null` **and** named in that object's `unknown` list, which is
its status. Every source key is either mapped to a v1 field or copied verbatim under `extra`, so nothing is
silently dropped (a test checks this for scanner records). Derived values are arithmetic on source fields only
(`fee_bp`, `cost_bp`, `cost_share`, `spread_bp`).

| Mismatch | Decision |
|---|---|
| `signal.class` and `signal.cost_rt_pct` are required in T6.1; the scanner writes `null` (trend_sma has no expected move or measured cost) | nullable in v1, listed in `unknown`. The front end renders `UNKNOWN`, never `TRADEABLE` |
| scanner extras `action`, `interval`, `params`, `family`, `evidence` | kept as v1 fields (`action` = `open`/`close`) |
| scanner's own `seq`/`run_id`/`ts_emit_ms` | kept under `signal.source` (`kind: scanner`); the envelope `seq` is the feed's |
| replay `strategy_signal` | → `signal` (`side L→LONG`, `id→signal_id`, `strategy→strategy_id`); `gate_status_at_fire` = the registry's status (the gate runs after a replay) |
| replay per-account `signal` / `close` | → `paper_fill` (OPEN/CLOSE) + `position` (OPEN/CLOSED). New field `account` (`net`, `gross`, `stress`, `bh_*`): these are separate scenario simulations of the same signals and must never be summed. `liquidity`, `spread_paid_bp`, `slippage_bp` are unknown (null). `model_version` = `replay-broker:<cost\|paper>` |
| `strategy_status` evidence from `gate.json` | `gate.verdict` PASS/FAIL/INSUFFICIENT_DATA → PASSED/FAILED/INSUFFICIENT. **No `gate.json` → `PENDING` and every evidence number null**, never a computed substitute |
| T6.1: "win_rate_pct and p_star_pct travel together". The gate's `trade_economics.mode` is `mean_net_vs_cost` for trend_sma (no fixed TP/SL, so p* doesn't apply) | new field `win_rate_basis`. `win_rate_pct` is non-null only when basis = `p_star` with `p_star_pct` set, or basis = `mean_net_vs_cost` with `expectancy_net_pct` and `cost_rt_pct` set. **The terminal's WinRate component must accept the second form** (T6.2 note) |
| `sharpe_oos` vs the gate's per-trade Sharpe | `sharpe_oos` stays null; the gate's number goes in the new `sr_per_trade_oos` (different units, so it's labelled rather than relabelled) |
| `regime.trend` enum `trend`/`range` vs the gate label `"bull, low-vol"` | bull/bear → `trend`, range → `range`, `high-vol`/`low-vol` → `vol`; the original `label` is kept |
| `is_window` split missing from older summaries | taken from `gate.json` `oos_window.from` |
| `trades.is`, `profit_factor_net` | not in the gate → null + `unknown` |
| `strategy_status.state` (SCANNING/…) | no source reports it → null + `unknown` |
| `quotes.msgs_per_s`, `chg_1m_pct`, `chg_1h_pct` | not computed yet → null + `unknown` (T6.1 had `msgs_per_s` required) |
| `quotes.ts_event_ms` | `null`: bookTicker has no exchange time; `quote_recv_ms` is receive time, `trade_ms` exchange time |
| `hello.fee_model.source` | adds `unknown` (LIVE_PAPER has no fee model yet); REPLAY uses the run's `costs.net` as `repo_assumption` |
| heartbeat latency/rates | null + `unknown` (not measured). `components.scanner/paper_engine` = `unknown` (adds the enum value): a quiet signal file proves nothing |
| recorder `clock` records (offset_ms, rtt_ms) | surfaced as `heartbeat.clock` (latest sample). No skew threshold is applied |
| recorder `gap` records | `gap` → `data_quality{kind: GAP, gap:{from_id,to_id,missing}}`, `reconnect` → `RECONNECT`, anything else → `OTHER` (new enum value) with the record under `extra` |
