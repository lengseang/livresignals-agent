# T0.16 — the window that judges a dead edge must end where the edge died

## Problem

On 2026-11-08 the loop shipped `_recent_edge_net()` so the §4c line for a
STOPPED edge could read its recent net beside its lifetime net:

```text
loose (n=1261, +3.37 net, last fill 2026-10-11; last 28d: n=17, -0.20 net) — STOPPED
```

That sentence was in the JOURNAL and in a test fixture. It is **not in any
report the owner receives**. Measured on the live book 2026-11-09:

```text
recent_edge_net keys: ['validated']
loose present? False
```

`_recent_edge_net()` windows `[now - 28d, now]`. `loose`'s last fill is
**2026-10-11T23:16Z**; the window opens **2026-10-12T13:03Z**. The window is
entirely *after* the edge's last trade, so `loose` has zero fills in it, is
absent from the dict, `_recent_clause()` returns `""`, and the line degrades to
the pre-fix wording. **A window anchored at report time can never contain a
STOPPED edge — the very population it was written for.** The harder an edge is
stopped, the more certainly it is excluded.

Two secondary defects found on the way, both in the same line:

1. **The journal's number was not reproducible.** "n=17, −0.20 net" is the
   `self_improve` disable-gate figure from `logs/self-improve.log`, which is
   computed with `_should_disable`'s own predicate (n≥15, wr<42, net<0). It is
   the cohort that *fired the rule*, not the edge's net over the 28 days before
   its stop. Recomputing an anchored 28d window on the collapsed book gives
   **n=1162, +4.55 net**. Quoting the gate's number as "the last 28d" was a
   second silent redefinition — the class of bug this whole line exists to fix.
2. **The two readers disagree on lifetime net for the same edge.** The report
   says `loose n=1261, +3.37`; `self_improve.stats_net_of` on the same closed
   rows says `n=1684, +6.25`. The report collapses multi-TF duplicates (797
   removed) — correct — but the gate does not. Not fixed here (out of scope for
   one PR; logged as T0.17).

## Options

**(a) Keep now-anchored window, accept the degradation.** Honest but useless:
the clause silently vanishes for exactly the edges it was built for, and the
fallback is indistinguishable from "no data".

**(b) Anchor each edge's window at its own last fill.** For edge *e* with last
fill *t_e*, window = `[t_e - days, t_e]`. For a live edge this is within a day
of now (edges fill continuously), so the number is unchanged in substance; for
a dead edge it measures **the window that got it stopped**, which is the only
window that explains the decision.

**(c) Print both windows** (now-anchored and fill-anchored).

## Choose (b)

The question the sentence answers is "why was this stood down?" — that is a
property of the edge's final trading period, not of today. Anchoring at `t_e`
makes the same code correct for live and dead edges, which is why (c) is
unnecessary: for a continuously-filling edge the two anchors differ by hours
and the extra clause is noise.

Implementation: `_recent_edge_net(trades, days, now=None, anchors=None)`.
`anchors` is `{edge: iso_ts}`; when an edge has an anchor its cutoff is
`anchor - days` and its upper bound is the anchor. Without an anchor the
behaviour is byte-identical to today (now-anchored), so every existing caller
and test keeps its meaning.

The clause text must also stop saying "last 28d", which asserts a window ending
today. It becomes `; 28d to last fill: n=…, ±X net`. A reader who sees
"to last fill" cannot mistake it for a live figure.

## Failure modes

| Mode | Mitigation |
|---|---|
| Anchor equal to the fill we are measuring → n≥1 always | intentional; window is inclusive on both ends |
| Edge fills again after the anchor is taken | anchor comes from the same `last_fill` map the line prints from, so the two cannot disagree within one report |
| Undateable anchor | skip the anchor, fall back to now; never date to now silently |
| n=0 even anchored (edge's window truly empty) | `_recent_clause` already suppresses on `n==0` |
| Two edges share an anchor | per-edge dict, no coupling |

**Adversarial review ("3 months later it failed: why?").** The likely failure is
that `last_fill` and the trades list diverge (one counts a fill the other
collapsed away), leaving n=0 on an anchored window and silently dropping the
clause again. Mitigation: the tests assert the clause is **present** for a dead
edge built from a real-shaped two-record book, so a regression is red rather
than silent. Second failure: someone reintroduces "last 28d" wording; a test
pins the phrase.

## Test plan

1. `_recent_edge_net` anchored at a dead edge's last fill returns that edge,
   now-anchored returns nothing (the exact live regression).
2. Anchored clause appears in the §4c line with "to last fill".
3. Live edge (no anchor) unchanged: still "last 28d".
4. Anchor with n=0 is suppressed.
5. Undateable/absent anchor falls back to now (no crash).
6. End-to-end: `analyze()`-shaped book with a dead `loose` renders the clause.
7. Phrase guard: "last 28d" never appears on an anchored (dead) line.
