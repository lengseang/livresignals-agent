# T2.4 · Design: news and sentiment ingest (paper only)

Status: design for T2.4. **Paper-only context data.** Nothing here reads an account or places an order.

## Problem

Phase 3+ needs event context (listings, hacks, regulation) and a slow regime input next to the tick data.
`docs/research/sources.md` (T1.2) found four public RSS feeds and the Fear & Greed index reachable from this
machine; CryptoPanic is paid-only and out of scope. We need a small, honest recorder for them: every headline once,
with the publish time the feed gave us (or `UNKNOWN`), the time we saw it, and which of the 15 paper-universe coins it
mentions.

## Facts (measured 2026-09-26 ~01:22 UTC, `.venv` CPython 3.12.3, urllib)

| Source | URL | Result |
|---|---|---|
| Cointelegraph | `https://cointelegraph.com/rss` | 200, RSS 2.0, 30 items; `<link>` carries `utm_*` params |
| The Block | `https://www.theblock.co/rss.xml` | 200, RSS 2.0, 20 items, `<ttl>5</ttl>` |
| Decrypt | `https://decrypt.co/feed` | 200, RSS 2.0, 34 items |
| CoinDesk | `https://www.coindesk.com/arc/outboundfeeds/rss/` | redirected to `.../rss` (no slash), 200, RSS 2.0, 25 items, `<ttl>5</ttl>` |
| Fear & Greed | `https://api.alternative.me/fng/` | 200 JSON: `value "74"`, `Greed`, `timestamp "1790380800"` (00:00 UTC), `time_until_update "81471"` |

All four feeds use RFC 822 `pubDate` with an explicit `+0000` offset. Fixtures in `tests/loop/fixtures/news/` are
these real responses trimmed to four verbatim `<item>` blocks each (bytes copied, nothing edited).

## Design

Package `src/trading/news/` (new, stdlib only, no new dependencies):

- `feeds.py`: the pinned source list and `fetch(url)` (urllib, 20s timeout, identifying User-Agent, redirects followed
  by urllib's default handler, which covers 308 on 3.12). Response size capped at 5 MiB.
- `parse.py`: `parse_feed(source, body, fetched)` reads RSS 2.0 `<item>` and, as a fallback for a format switch,
  Atom `<entry>`. `parse_fng(body, fetched)` reads the index. `parse_published(raw)` returns `(utc_iso | None, status)`.
- `tags.py`: `tag_symbols(text)` returns the sorted tickers found in title + description text.
- `store.py`: `NewsStore(root)` appends JSONL to `<root>/<YYYY-MM-DD>.jsonl` (date = **fetch** time, UTC) and
  dedupes by key. Seen keys are rebuilt at start-up by reading the existing JSONL files, so the files are the only
  state and can't drift from an index.
- `run.py`: `python -m trading.news.run --once | --every-minutes N [--out data/local/news]`.

### Record shapes (one JSON object per line)

```
{"kind":"news","source":"coindesk","url":"https://…","title":"…","published_utc":"2026-09-25T22:17:38Z",
 "published_status":"OK","published_raw":"Fri, 25 Sep 2026 22:17:38 +0000","fetched_utc":"…Z","symbols":["BTC"]}
{"kind":"fng","source":"alternative.me","value":74,"classification":"Greed","index_time_utc":"…Z",
 "index_time_status":"OK","time_until_update_s":81471,"fetched_utc":"…Z"}
{"kind":"fetch_error","source":"decrypt","url":"…","error":"URLError: …","fetched_utc":"…Z"}
```

### Choices

- **Publish time is never invented.** `published_raw` is always kept. The parsed value is `OK` only when the string
  parses *and* carries a zone (`+0000`, `GMT`, `Z`, `-0000`…). No zone, garbage, or a missing tag gives
  `published_utc: null, published_status: "UNKNOWN"`. We never substitute the fetch time.
  Pitfall found while testing: `email.utils.parsedate_tz` returns offset **0** both when the zone is missing and when
  it is a name it doesn't know (`CEST`), which would silently relabel local times as UTC. We therefore only accept a
  numeric offset or one of the zone names email.utils really maps; anything else is `UNKNOWN`.
- **F&G numbers are never invented.** A missing or non-integer `value` is `null`; a missing timestamp is `null` with
  `index_time_status: "UNKNOWN"`. F&G is daily; it is deduped by `index_time_utc`, so polling every 5 min writes one
  row per day (plus one per run if the time is UNKNOWN, which is loud on purpose).
- **Dedupe key = canonical URL**: scheme and host lower-cased, fragment dropped, `utm_*` query params dropped (other
  params kept). Without this, Cointelegraph's tracking params would make the same article look new if they rotate.
  Items without a link (or a permalink `guid`) are skipped: no key, no dedupe. Cross-source duplicates of the *same story* at
  different URLs are kept: they are different articles.
- **Errors are data.** A failed fetch, a parse error, or a feed that parses to zero items writes a `fetch_error` row,
  like the stream recorder writes gap rows. One source failing never stops the others.

### Symbol tagging and its false-positive risks

Word-boundary regex over title + description (HTML stripped). A coin is tagged when either:
1. its **ticker appears in capitals** (case-sensitive `\bBTC\b`; `$BTC` matches, `WBTC`/`stETH` don't), or
2. its **full name** appears. Unambiguous names match case-insensitively (bitcoin, ethereum, solana, cardano,
   chainlink, dogecoin, arbitrum, polkadot, litecoin); ambiguous names match only **capitalised**
   (`Ether`, `Avalanche`, `Sui`, `Cosmos`) and NEAR needs the ticker or `Near Protocol`.

Known risks, accepted and documented rather than hidden:
- `LINK`, `NEAR`, `DOT`, `ATOM`, `SUI` in an ALL-CAPS headline ("NEAR RECORD HIGH") tag falsely. Our four feeds use
  sentence/title case (checked on 109 live items), so this is rare.
- `ADA` also names the US disabilities law; `SOL`/`ARB` appear in other acronyms. Caps-only tickers still collide.
- `Avalanche`/`Cosmos` at the start of a sentence in a non-crypto sense ("Avalanche of lawsuits") tags falsely.
- `Ether` also matches the non-crypto word when capitalised. `XRP` is tagged by ticker only; "Ripple" (the company)
  deliberately does not tag XRP. "Binance" does not tag BNB (the exchange is not the coin).
- Descriptions add recall but also noise. Observed on the first live run: an obituary tagged `SOL` because the
  description says the person "held senior roles at Stellar and Solana". Tags are context for a human or a
  later scorer, never a trade trigger on their own.

## Rate and etiquette

- `--every-minutes` below **5** is rejected (The Block and CoinDesk advertise `<ttl>5</ttl>`; F&G updates daily).
- Sequential requests, one per source per cycle, identifying User-Agent, no retries inside a cycle (the next cycle
  is the retry). Conditional GET (ETag / If-Modified-Since) is a possible later saving; not needed at this volume.

## Failure modes (pre-mortem: it's 3 months later and this failed, why?)

- **Feed format change** (RSS → Atom, renamed tags, a date format without a zone). Atom is parsed as a fallback; a feed
  that yields zero items writes a `fetch_error` row every cycle, so the break is visible in the data, and an
  unparseable date becomes `UNKNOWN`, never a guessed time.
- **Silent redirect to a consent/HTML page.** Parsing HTML as XML fails or finds zero items → `fetch_error`.
- **Hostile or huge XML.** stdlib `xml.etree` is the owner's constraint (no `defusedxml` dependency). CPython 3.12's
  expat does not fetch external entities, and we additionally **refuse any payload containing `<!DOCTYPE`/`<!ENTITY`**
  (RSS never needs one) and cap the body at 5 MiB, which removes the entity-expansion vector.
- **Tracking params change name** (not `utm_*`) → the same article is recorded twice. Detectable by a duplicate-title
  check in analysis; acceptable noise.
- **Dedupe state grows.** ~100 new items/day; scanning all JSONL at start-up stays in the low milliseconds for years.
- **Clock skew.** `fetched_utc` is the local clock; publish-to-fetch lag stats inherit that skew (reported, not fixed).

## Test plan (`tests/loop/test_news.py`, no network)

1. Each real fixture feed parses to 4 items with UTC `published_utc`, `OK` status, and the right canonical URL.
2. `parse_published`: garbage, empty, `None`, and a zone-less date → `(None, "UNKNOWN")`; `+0200` converts to UTC.
3. Tagger: true positives from the fixtures (Bitcoin, BTC, Ethereum, XRP, Solana); negatives (`Binance`, `WBTC`,
   lowercase `link`/`near`/`dot`/`atom`, "Ripple").
4. F&G fixture parses to value 74 / Greed / 2026-09-26T00:00:00Z; missing fields → `null` + `UNKNOWN`.
5. Store: dedupe within a run and across two store instances over the same directory; file named by fetch date.
6. `run_once` with an injected fetcher: one failing source writes a `fetch_error` and the rest are still written;
   an empty feed writes a `fetch_error`; `<!DOCTYPE` payloads are refused.
7. CLI rejects `--every-minutes 4`; the package imports no exchange client.
8. Opt-in live smoke test (`@pytest.mark.network`, `LOOP_NETWORK=1`).
