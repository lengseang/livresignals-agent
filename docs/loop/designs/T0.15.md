# T0.15 — the real-money universe did not widen when the paper universe did

Status: review (branch `loop/T0.15-real-syms-copy-drift`)

## Problem

`scripts/trend_follower.py` holds two lists:

```text
SYMS       53 USDT pairs — what the strategy STUDIES (expanded 2026-09-17, +38)
REAL_SYMS  15 USDT pairs — what real money may OPEN
```

The entry loop iterates candidates drawn from the full paper universe and
`continue`s on anything not in `REAL_SYMS`. The printed run line shows the
**paper** held list, then reports `real positions: 0/3 | REAL=ON`.

Measured 2026-11-07 against the live host (`logs/trend.log`, `data/trend-state.json`,
read-only):

```text
[2026-11-07 12:10] TREND v2 | long 3/53: ['INJ/USDT','ONE/USDT','PEPE/USDT']
  real positions: 0/3 | REAL=ON
  (16:10 run identical; 0 REALBUY / 0 ERR / 0 "entry blocked"
   lines in the whole 2026-11-05 → 2026-11-07 window)
```

`INJ`, `ONE`, `PEPE` are not in `REAL_SYMS`. Every candidate the strategy
picked was filtered by the real-money gate, correctly, and **nothing said so**.
A reader of the log sees the strategy in three uptrends and zero real positions
and has to open the source to learn why.

The same list is typed out three more times (`trend_gate_test.py`,
`trend_exit_ab.py`, `trend_trail_test.py`) — the universe-copied-many-times
class that already cost this stack a missing `15m` timeframe for weeks.

## Why this is not "just widen the list"

Widening `REAL_SYMS` is a real-money scope change. `promotion_report.py`
documents the bar (>=55% win rate over >=15 recorded paper trades), and the
selection of 15 coins was an owner decision. The bug is the **silence**, not
the narrow list: the path is behaving as designed.

## Options

1. Widen `REAL_SYMS` to the paper universe. Rejected — scope change, would put
   real money on coins that never passed the promotion bar, in a market where
   breadth is 0up/8down.
2. Make the skip log-only (`print`). Cheap, but the owner reads cards, not logs,
   and the card is where "needs attention" is decided.
3. **Emit an explicit non-act event** (`INFO`) carrying the declined symbols,
   render it in the card under `ℹ️ Did not act`, and append the same count to
   the run line. Chosen.
4. Promote the list to a shared module. Right long-term; it changes imports in
   four scripts, which is more than one change per PR. Deferred to a test that
   fails when a copy drifts, and a TASKS note.

## Change (one behaviour, one PR)

- `paper_only_skipped(candidates, real_syms)` — pure helper, returns declined
  names in order.
- Entry loop appends `("INFO", ...)` when the set is non-empty.
- `_build_message` gains an `INFO` branch rendering a `Did not act` block;
  `n_change` excludes `INFO` (it is a reason, not a change).
- Run line appends ` | paper-only N: [...]` when non-empty.

Nothing on the order path changed: no parameter, no size, no stop, no gate
threshold, no `REAL_SYMS` membership.

## Failure modes (pre-mortem: "it is 3 months later and this failed — why?")

1. **Card spam** — every 4h run in a paper-only uptrend now sends a card. Card
   volume today is near zero (no REALBUY in 3 days), and the notify path
   swallows send errors; acceptable. If it becomes noisy, dedupe on the symbol
   set in `notify_state`.
2. **INFO counted as a change** — the title would read `4 changes` for one buy.
   Pinned by a mixed-list test; the first draft of that test passed the mutation
   (single-event list), which is why the final test asserts both directions.
3. **Copies drift again** — the duplicate-copy test evaluates each copy's
   literal and fails on inequality, so the next person to widen `REAL_SYMS`
   without touching the research scripts is told. It permits exactly the three
   copies that exist today.
4. **Helper grows semantics** — it must stay a pure filter; the test asserts it
   returns `[]` when every candidate is real.
