# T0.20 — the run log drops the reason and prints `None`

**Status:** design + pure helper shipped; one-line call-site change in
`scripts/trend_follower.py` is **owner-gated** (E16).

## Problem

`scripts/trend_follower.py:708-709` prints every event with one format:

```python
for kind, sym, px, extra in events:
    print(f"  {kind} {sym} @ {px}")
```

That format assumes every event has a **symbol** and a **price**. `OPEN`, `EXIT`,
`REALBUY`, `REALEXIT` do. The two non-trade kinds do not:

- `INFO` is emitted (`:653`) as `("INFO", "trend", None, "<the reason>")`
- `ERR` is emitted (`:640`, `:645`) the same way — `("ERR", "trend", None, "<reason>")`

For both, the line renders as `  INFO trend @ None` / `  ERR trend @ None`:
the symbol slot is a sentinel (`"trend"`), the price slot is `None`, and — the
actual defect — **`extra`, which is the entire reason the event exists, is never
printed.**

Measured on the live host, 2026-11-11:

```text
$ grep -c "INFO trend" logs/trend.log
4
$ grep -nE "^  [A-Z]+ .* @ (None|\{)" logs/trend.log
879:  INFO trend @ None
908:  INFO trend @ None
916:  INFO trend @ None
920:  INFO trend @ None
```

Every occurrence is `INFO`. All four sit directly under an `OPEN <sym>` line. That
is structural, not coincidence: with `real positions: 0/3`, the INFO event is only
reached on a run with a non-empty `candidates` list that is not `buys_blocked`
(`:648`), i.e. exactly the runs where a **paper** position opens. So the operator
reading `logs/trend.log` gets

```text
  OPEN ONE/USDT @ 0.001866
  INFO trend @ None
```

and the reason — `"3 candidate(s) paper-only (not in REAL_SYMS): INJ/USDT, …"` —
exists only in the Telegram card (`_build_message`, `:501-505`), which the log
does not record. Anyone diagnosing from the log sees a symbol position saying
`trend` and a price saying `None`.

### Why the tests did not see it

`tests/loop/test_trend_real_symbol_scope.py` tests `_build_message` (the card) and
`paper_only_skipped` (the helper). **No test exercises the event printer**, and no
test calls `main()`. This is the JOURNAL's own 2026-11-09 lesson repeating:

> if a test injects the value whose absence is the bug, the test cannot see the bug.

The card was fixed and tested; the log line beside it was neither.

## ⚠️ Corrected during build — `ERR` is NOT a notice kind

The first draft of this design classified events by *kind*: trade kinds
(`OPEN`/`EXIT`/`REALBUY`/`REALEXIT`) vs notice kinds (`INFO`/`ERR`). That is
**wrong**, and reading all `events.append((` sites in `trend_follower.py` proved it
before a line of code shipped:

- `INFO` — **1 site only** (`:653`), always `("INFO", "trend", None, reason)`.
- `ERR` — **11 sites**. Exactly **2** are symbol-less notices (`:640`, `:645`,
  both the "buys blocked" / "live switch OFF" case). The other **9** pass a real
  symbol *and a reason*: `("ERR", it["symbol"], None, f"intent … dropped")` at
  `:219, 223, 229, 234, 236, 240, 370, 398, 408, 424, 443, 693`.

So a kind-based rule would have reformatted 9 working `ERR` lines that today print
`  ERR INJ/USDT @ None`, and — worse — would have dropped the reason from them,
turning "one `None` on four INFO lines" into "one `None` on every ERR line plus a
silently swallowed reason". **The bug is narrower and the rule is different.**

### The real discriminator: does the event carry a symbol?

The defect is not the kind. It is that `sym is None` is a **sentinel** meaning
"there is no symbol here", and the printer has no branch for it. That holds for
`INFO` (always) and for 2 of 11 `ERR` sites. The rule is therefore:

```text
event has a symbol      -> "  KIND <sym> @ <px>"   unchanged, byte-for-byte
event has no symbol     -> "  KIND <reason>"       INFO x1, ERR x2
```

`px is None` is **not** part of the rule: `ERR`, `OPEN`, `INFO` all pass a `None`
price in places, and `  ERR INJ/USDT @ None` is what the operator has been reading
for the failure path — correct and unchanged. Only the sentinel symbol is the bug.

Live measurement (2026-11-11): `grep -c "^  ERR " logs/trend.log` → **0**. So the
9 ERR lines have no live instances to break, but the source is unambiguous and the
`ERR`-with-symbol sites are exactly the messages that matter if one ever fires.

## Options

1. **Print `extra` only for non-trade kinds.** `if sym is None: print(f"  {kind} {extra}")`.
   Minimal, but hard-codes the sentinel `"trend"` as a stand-in for "no symbol" —
   a real symbol called `trend` would be mis-rendered, and the rule is invisible.
2. **Mirror the card's switch.** A `log_line(kind, sym, px, extra)` that knows which
   kinds are *position* events (need sym+px) and which are *notices* (need the text).
   Explicit, testable, and the two artefacts then agree by construction.
3. **Emit a dict/structured JSON.** Best long-term, but changes the log format the
   owner reads and the greps the board already relies on (`grep -c REALBUY`).

## Choice

**Option 2**, implemented as a pure function `event_log_line()` in the loop's own
module `src/trading/ops/event_log.py`, because:

- `scripts/trend_follower.py` is on the **never-edit** list (LOOP.md §2). The loop
  may not touch it; the owner applies a one-line call-site change (E16).
- A pure function is testable without an exchange, a state file or an order path —
  the same constraint every `tests/loop/` test lives under.
- The function is written so that the *call site* is the current two lines
  verbatim: `print(event_log_line(kind, sym, px, extra))`, preserving the leading
  two spaces and the `  KIND …` shape.

Discriminator: **`sym` is `None` or empty** → notice branch (`  KIND <reason>`).
Everything else keeps `f"  {kind} {sym} @ {px}"` exactly as today, so existing
greps and the board's quoted lines stay byte-identical. A missing reason renders
`(no reason recorded)` rather than `None`, per standing rule 2 (never print a
plausible-looking non-value).

## Failure modes (adversarial self-review — "it failed in 3 months, why?")

1. **The owner applies the helper but the reason is still swallowed.** Covered: the
   helper is the only thing that formats the line, and a test asserts the reason
   substring appears for a symbol-less `INFO` *and* a symbol-less `ERR`.
2. **A symbol-carrying `ERR` is re-routed into the notice branch**, dropping its
   price and `sym`. This is the mistake the first draft of this design made.
   Covered by controls that pin all four trade kinds **and** a symbol-carrying
   `ERR` to today's exact bytes.
3. **`extra` is a dict for some kinds** (`EXIT` passes `{"ret", "why", "real"}`).
   The helper must not `str()` a dict into the log; the trade branch ignores
   `extra` entirely, as today.
4. **A new kind is added with `sym=None` for a real fill** — it would lose its
   price. Accepted: `sym=None` means "no symbol" by construction; a fill with no
   symbol is a different bug. The test reads every `events.append((` site in
   `trend_follower.py` and asserts each `INFO`/`ERR` with a `None` symbol has a
   non-empty reason, so a symbol-less fill would show up as a test failure.

## Test plan

`tests/loop/test_event_log_line.py`:

- `INFO` with the live 2026-11-10 payload → line contains the reason, no `None`.
- Symbol-less `ERR` (live kill-switch payload, `:645`) → same.
- **Control (the one that matters):** symbol-carrying `ERR`
  `("ERR", "INJ/USDT", None, "sell failed (attempt 2): …")` → byte-identical to
  `"  ERR INJ/USDT @ None"`. Plus `OPEN` / `EXIT` / `REALBUY` → identical to
  `f"  {kind} {sym} @ {px}"`.
- Empty / `None` reason → `(no reason recorded)`, never `None`.
- Source sweep: every `events.append((` site in `scripts/trend_follower.py` whose
  symbol literal is `None` carries a non-empty reason (regex over source text, no
  import of the live module).
- **Mutation checks:** (M1) route on `px is None` instead of `sym is None` → the
  symbol-carrying `ERR` control goes red; (M2) drop `extra` for notices → 2 red;
  (M3) `str(extra)` in the trade branch → `EXIT` control red (dict leaks in).
