# T0.6 · Design: `live_executor.manage()` reconcile and invented numbers (F4)

Status: **design only, waiting on the owner.** Order code; implementing it is T8.1.

## Reframe first

`manage()` is gated on `config/LIVE_ENABLED` (`scripts/live_executor.py:363`), and git only holds
`config/LIVE_ENABLED.retired-intraday-2026-09-12`. If the flag is absent on the VPS (E1 asks),
this book is **dormant**, yet cron still starts it every 10 minutes (`config/crontab.trade`,
`6-56/10 * * * * ... live_executor.py manage`).

So the first decision is whether this book should exist at all, not how to fix it:

- **Option 0 (recommended): retire it properly.** Remove the cron line (an owner action: the crontab is
  on the no-touch list) and leave the code in place with a header saying it's retired and
  unsafe to re-enable without this design. It costs nothing and removes a live hazard (below).
- **Option 1: fix it** as designed below, only if intraday live trading is coming back.

## Problems (read from the code)

1. **It sells coins that aren't its own.** On exit, it sells the **entire free balance** of the
   base asset (`:470-485`). Its universe `ALLOWED_REAL` (`:38`) overlaps `trend_follower`'s
   `REAL_SYMS` (DOGE, SOL, XRP, ADA, LINK, AVAX, BNB, SUI), and both use the same account
   (`make_live_exchange()` reads `config/live.env`, `live_client.py:20`). With the flag on,
   one exit here would liquidate the trend book's position in that coin. **This is the most
   dangerous line in the repo if the flag is ever restored.**
2. **An invented quantity.** `if free <= 0: free = pos["size_usdt"] / pos["entry"]` (`:474-475`)
   sells a computed amount the wallet may not hold.
3. **An invented exit price.** The normal close records `exit = px` (the ticker) and
   `pnl = (px - entry) * qty` (`:486-487`), although `place_market_sell` returns the real average fill
   (`live_client.py`, `price = total_cost / total_qty`). The self-heal records `exit_px = real_px if
   real_px else px` (`:399`), which falls back to the current price when no sell is found. Both break owner rule 2.
4. **Partial drift is ignored.** Self-heal triggers only when `held < 10%` of the booked quantity (`:385`).
   A wallet holding 40% (the 58 → 23 DOGE shape) is treated as fully held.
5. **A single save after all sells** (`:497`). A kill after `place_market_sell` and before `_save`
   leaves the position open, and the next pass sells again: the full free balance, per problem 1.
6. **A corrupt state file reads as empty** (`_load`, `:93-100`), the same defect as T0.3 path B.

## Design (Option 1)

This reuses the primitives from T0.3–T0.5 instead of re-inventing them. Because two scripts need the same
order-safety logic, the implementation extracts it once into `scripts/real_order_journal.py`
(atomic save, fail-closed load, a run lock, write-ahead intent with a `clientOrderId`, a resolver,
closed records with `*_status`) and both scripts call it. Two hand-written copies would drift, and this
repo's history (`book_units.py` exists because readers diverged three times) shows that it does.

1. **Sell only your own quantity:** `qty = min(pos.qty, free)`, rounded down to the lot step. Never the
   whole free balance. Never `size_usdt / entry`. If `pos.qty` is unknown, don't sell; alert.
2. **Reconcile every drift, not only < 10%:** if `free < pos.qty` (beyond one lot step), record
   `qty_drift: {booked, held, seen_ts}`, alert, and manage the smaller held amount from then on. The
   missing part is resolved from the trade history (VWAP, `TRADE_HISTORY`) only when the quantities reconcile;
   otherwise it gets a partial close record with `exit: null, exit_status: UNKNOWN`.
3. **Exit price from the fill:** `exit = sell["price"]` and `qty = sell["amount"]`. If `price == 0.0`
   (`place_market_sell` returns 0.0 when there were no fills), then `null` / `UNKNOWN`. Delete the `px` fallback at `:399`.
4. **Write-ahead intent per sell** with a `clientOrderId`, saved before the sell. The next pass resolves it
   before doing anything else (T0.3 §4 table, applied to sells). This also closes problem 5.
5. **Fail closed on a corrupt state file** (T0.3 §2).
6. **Ownership check on start:** refuse to manage any symbol that `trend-state.json` `real.open` also holds,
   and alert. Two books in one wallet must never trade the same coin.

## Pre-mortem

- **The owner restores `LIVE_ENABLED` for a quick test before this lands.** Problem 1 then fires on
  the first exit. Mitigation: Option 0 plus a loud header comment. Removing the cron line is the only
  thing that makes this impossible by accident.
- **The shared module becomes a new single point of failure.** It will be the most-tested file in the repo:
  every T0.3–T0.6 test case runs against it through both scripts.
- **`place_market_sell` bypasses ccxt's `create_order`** (it calls `privatePostOrder` directly,
  `live_client.py:148`; the buy does the same at `:115`), so `clientOrderId` must be passed as `newClientOrderId` in that raw request.
  The implementation must add it there; the ccxt `params` path from T0.3 doesn't apply to this call.

## Test plan (for T8.1)

Fake exchange, no network:
1. Free balance > position qty: sells exactly `pos.qty` and leaves the rest.
2. `free <= 0`: no sell, alert, nothing invented.
3. The sell returns `price == 0.0`: exit `null`/UNKNOWN, `pnl` null.
4. Held 40% of booked: drift recorded and managed at 40%; the missing part is UNKNOWN unless the trade history reconciles.
5. Kill after the sell and before the save: the next pass resolves the `cid` as FILLED and does not sell again.
6. A symbol also in `trend-state.json` `real.open`: refused, alert.
7. Corrupt `live-trades.json`: no action, non-zero exit.
