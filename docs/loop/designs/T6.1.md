# T6.1 · Design: operator terminal (layout, feed contract, square-corner style)

Status: design only, for T5.1 (feed API, agent repo) and T6.2/T6.3 (front end, `livresignals` repo).
No front-end code in this PR. **Read-only and paper-only:** everything the terminal shows is SIMULATED,
labelled `LIVE_PAPER` or `REPLAY`. Real-money data is out of scope and the client refuses it (§4.1).

## 0. Facts this design is built on (read from the repos, 2026-09-26)

Agent repo (`livresignals-agent`, base `loop/T2.6-full-history`):
- Tick schema `src/trading/stream/normalize.py`: `Tick(kind ∈ {book, trade, kline}, symbol, ts_exchange_ms | None,
  ts_recv_ns, data)`. `bookTicker` carries **no exchange timestamp**, so its `ts_exchange_ms` is `None` and is never
  back-filled. Gaps are recorded, never interpolated (`gaps.py`: `{"kind":"gap","symbol","from_id","to_id","missing"}`).
- Measured load (T2.1): 15 symbols × {bookTicker, aggTrade, kline_1s} ≈ **540 msg/s**. The browser must never see
  this raw rate (§4.4).
- Clock skew: `ts_recv` is `time.time_ns()`, not corrected (T2.1 pre-mortem). Any cross-clock latency is labelled.
- Fee reality (`docs/research/fees-and-breakeven.md`): break-even win rate `p* = (sl + c) / (tp + sl)`,
  `c = 2(f + s)`; the account's real fee rate is **UNKNOWN**; spread/slippage are **UNKNOWN** until T2.3.
- Gate (`docs/research/strategy-audit.md`): Deflated Sharpe with every generated variant counted as a trial, positive
  OOS, BTC buy-and-hold comparison, regime stated, win rate next to its own `p*`.
- Honesty file `config/execution-status.json`: `simulated: true`, `badge: "SIMULATED"`, `real_capital_deployed: false`.
- Installed feed stack (`requirements.txt` and `.venv`): `fastapi==0.141.1`, `starlette==1.6.0`, `uvicorn==0.52.2`.
  FastAPI 0.141.1 ships `fastapi.sse` with `EventSourceResponse` and `ServerSentEvent(data, event, id, retry, comment)`,
  sends a `: ping` keep-alive comment when a generator is idle (`_PING_INTERVAL = 15.0` s), and documents that the
  browser returns `id` as `Last-Event-ID` on reconnect. **No new Python dependency is needed for SSE.**

Front-end repo (`livresignals`, working tree read-only; LOOP.md §4 says local `main` is behind `origin/main`, and this
agent could not read `origin/main` from its isolated worktree, so **T6.2 must re-check these against `origin/main`**):
- `package.json`: `next 15.5.25`, `react 19.0.0`, `react-dom 19.0.0`, `lightweight-charts ^5.2.1`, `animejs ^4.5.0`,
  `tailwindcss 3.4.17`, `typescript 5.7.3`. Four runtime deps; `AGENTS.md` §5 makes adding one a product decision.
- No `node_modules` on this machine; `tsc` and `next build` can't run locally (the guards' own docstrings say so).
- `lightweight-charts` usage already in repo (`components/chart/LiveCandleChart.tsx`): `createChart`,
  `chart.addSeries(CandlestickSeries, …)`, `createSeriesMarkers`, `SeriesMarker<Time>`, loaded via `next/dynamic`
  with `ssr: false` (`ChartSlot.tsx`). The terminal reuses exactly these calls; no other chart API is assumed.
- Tokens (`tailwind.config.ts`): `bg.0–4`, `line.*` (alpha-baked 8-digit hex), `ink.{DEFAULT,muted,faint,ghost}`,
  `profit.*`, `loss.*`, `accent.*` (brass), `focus`, radius scale `sm 4px … xl 16px`, two motion curves.
  `AGENTS.md` §5: changing a colour, font or motion token is an **ask-before** trigger.
- Root `app/layout.tsx` mounts `AuroraBackdrop` (fixed, animated blur blobs) for every route.
- Fonts: Inter + JetBrains Mono via `next/font` (`lib/fonts.ts`). Doctrine: **monospace for identifiers, never money**;
  tabular figures on `table`, `.tnum`, `time`, `output`.
- `AGENTS.md` §2 "THE ONE RULE": every number on the site is traceable to `public/data/ledger.json`. The terminal's
  numbers come from the feed instead, so it needs its own, equally strict rule (§5) and must stay a separate surface.

## 1. Goal and non-goals

**Goal.** One screen, open 24/7 on the operator's machine, that answers within a glance:
is the system alive and current; what did the scanner just see and fire; what are the paper positions doing net of
cost; which strategies have *earned* attention (survived the gate) and which are noise.

**Non-goals.** No order entry, no buttons that change state, no real-money data, no public marketing surface,
no mixing with the published hash-chained record. The feed exposes `GET` only, so "read-only" is structural,
not a UI convention.

### 2.2 Panels: what each shows and how often it updates

| Panel | Shows | Source | UI update rate |
|---|---|---|---|
| Top bar | SIMULATED + mode badges, feed state, last seq, heartbeat age, browser↔feed RTT, clock-skew estimate, dropped-event counter, UTC clock, scanner size, gap count, uptime | `heartbeat`, `/v1/ping` | 1 Hz (clock and ages), RTT every 2 s |
| Symbols | every symbol in the paper universe: last, bid/ask, spread in bp, Δ1m/Δ1h, msg rate, **data age**; gap flag | `quotes` | 1 Hz (server-conflated) |
| Chart | 1s candles for the selected symbol (1m/5m/1h selectable), signal markers, paper fill markers, TP/SL lines of open paper positions | `candle`, `signal`, `paper_fill`, `GET /v1/candles` | per candle event (1 Hz) |
| Positions | open paper positions: side, qty, entry, mark, **NET % and GROSS %**, modelled cost in bp, cost share of move, age, strategy; closed today collapsed | `position`, `paper_fill` | 1 Hz |
| Signal tape | every `signal` event, newest on top; TRADEABLE vs OBSERVED (expected move below cost, per the T1.1 rule); pausable | `signal` | per event, rendered at most once per animation frame |
| Strategies | evidence table (§3.3), gated survivors by default | `GET /v1/strategies` + `strategy_status` deltas | 0.2 Hz (5 s batches) |
| Scanner | cycle duration p50/p99, strategies evaluated per cycle, signals per minute, firing heatmap (strategy family × minute) | `scan_cycle` | per cycle, rendered ≤ 1 Hz |
| Latency | per-hop latency (§4.5) with 5-min sparklines, WS reconnects, per-stream msg rates | `heartbeat`, `/v1/ping` | 1 Hz |
| Data quality | append-only log of gaps, reconnects, stale streams, skew warnings, contract violations | `data_quality`, client | per event |
| Fills | paper fills: price vs reference, fee, spread paid, modelled slippage, modelled latency, maker/taker, **non-fills** | `paper_fill` | per event |

"Live scalping" is not a separate screen: scalping strategies are a family. The `SCALP` filter (`:scalp`) narrows the
tape, positions and fills to that family and adds a **cost-share** column (fees + spread + slippage ÷ |gross move|),
because at our tier cost share is the number that decides whether a scalp exists at all.

### 2.3 States (every panel implements all five)

| State | Trigger | Rendering |
|---|---|---|
| AWAITING | no snapshot yet | panel title + `AWAITING SNAPSHOT` text; no skeleton shimmer, no zeros |
| EMPTY | snapshot says there is nothing | an explicit sentence with the count: `0 open paper positions`. Never a blank box |
| LIVE | data fresher than its threshold | normal |
| STALE | age > threshold (quotes 3 s, heartbeat 3 s, strategy batch 15 s) | values stay visible but drop to `ink-ghost`; an amber `STALE 14s` tag with the age as **text**; colour is never the only signal |
| LOST | heartbeat age > 10 s, or EventSource closed | full-width amber banner `FEED LOST 00:32 · values frozen at 14:03:07Z · retry 3`; every panel goes STALE; nothing is cleared |
| CONTRACT ERROR | a payload fails validation (§4.1) | the payload is dropped, counted in the top bar, logged in Data Quality with the reason; a red `CONTRACT` tag on the top bar until acknowledged (`Esc` on the tag) |

Thresholds are constants in one file so they're visible and testable. REPLAY staleness uses wall-clock heartbeat age,
never simulated time.

### 2.4 Keyboard-first interaction

Everything is reachable without a mouse; the mouse works too.

| Key | Action |
|---|---|
| `F1`–`F5` or `1`–`5` | focus Symbols / Chart / Positions / Tape / Dock |
| `Tab` / `Shift+Tab` | cycle panel focus |
| `j` `k` / `↓` `↑` | move row selection; `g` `G` top/bottom; `PgUp` `PgDn` page |
| `Enter` | drill in: symbol → chart; strategy → evidence drawer; signal → its strategy and chart marker |
| `Esc` | close drawer / clear filter / acknowledge a CONTRACT tag |
| `/` | filter the focused table (substring; `fam:mom`, `gate:failed`, `sym:BTC` prefixes) |
| `:` | command line: `:sym BTCUSDT`, `:tf 1m`, `:strat mom-h1/*`, `:scalp`, `:mode replay <run_id>`, `:mode live`, `:all` (show every gate state), `:survivors` |
| `p` | pause/resume the tape (new events count in the header: `PAUSED +37`) |
| `s` / `S` | next/previous sort column in the focused table |

| `?` | key map overlay |

Rules: single-letter keys are ignored while an input has focus; there are no destructive keys because there are no
actions; the focus ring is a 1px `term-cyan` outline, square, offset 0.

## 3. What the terminal must show about evidence

### 3.1 Honesty rules on screen (enforced by component types, not by care)

1. **SIMULATED is always visible**, with the mode (`LIVE_PAPER` or `REPLAY <run_id>`). Screenshots can't crop it
   out cleanly because it also appears in each panel title (`POSITIONS · paper · LIVE_PAPER`).
2. **No win rate without its break-even.** The `WinRate` component's props require `pStar` (`number | null`) and `n`.
   It renders `58.1% (p* 52.5%) n=212`, with the margin `+5.6pp` coloured by sign *and* signed with `+`/`−`.
   If `p*` is `null` it renders `p* UNKNOWN` and greys the win rate. There is no way to render a bare win rate.
3. **Gross vs net is always labelled.** Column headers say `NET` or `GROSS`; NET comes first and is the default sort;
   GROSS never appears without NET beside it. The fee basis is always shown: `fee: measured` /
   `fee: VIP0 scenario` / `fee: repo assumption 0.144% rt` (from the feed's `fee_model.source`).
4. **Stale is grey, with its age as text** (§2.3). A number never looks current when it isn't.
5. **Unknown is `UNKNOWN`, never `0` or `—` pretending to be a value.** `null` in the feed renders `UNKNOWN`.
   No client-side fallback numbers, no client-side recomputation of evidence (the feed owns the maths, like
   `lib/derive-*.ts` owns it on the site).
6. **Every rate carries its sample size** (`n=`). Below the gate's minimum trade count the row is `INSUFFICIENT`, not
   ranked.
7. **Survivorship is visible.** The strategy header always shows total strategies and counts per gate state; DSR is
   shown with its trial count `0.97 (3 480 trials)`.
8. **REPLAY and LIVE_PAPER never share a screen.** One mode per connection; switching mode clears and re-snapshots.
   REPLAY gets a violet mode badge and a hatched panel-title strip so a screenshot can't be mistaken for live paper.
9. **Default sort is Deflated Sharpe, never win rate.** Win rate is sortable, but the sort indicator reads
   `sorted by win rate (not evidence)`.
10. **No ledger numbers.** The terminal never displays `ledger.json` statistics; the published record and the paper
    lab are different things and must not be visually merged.

### 3.2 Presenting thousands of strategies

- **Default view = gated survivors** (`gate.status == PASSED`), with the full counts in the header. `:all` shows every
  state; FAILED rows render in `ink-ghost` with their first failing reason (`OOS negative`, `DSR < threshold`,
  `below p*`, `n < min`).
- **Server-side filter, sort and pagination** (`GET /v1/strategies`, cursor-based) once the registry exceeds
  5 000 rows; below that the client may hold the full list (≈1 KB/row ⇒ ≤ 5 MB).
- **Virtualized table**, hand-rolled (fixed 20 px rows, absolute positioning inside a spacer of `rows × 20px`,
  overscan 10). Hand-rolled because a virtualization library would be a new dependency (`AGENTS.md` §5) and fixed
  row height makes windowing ~60 lines of code. The DOM holds only visible rows (~40).
- **Grouping** by family (collapsible, with group aggregates: count, survivors, best DSR, signals/24h) and by symbol.
- **Delta updates**: `strategy_status` carries only changed rows every 5 s; the client patches by `strategy_id`.
  A row whose values changed shows a 1 px left rule in `term-cyan` for 2 s. No flashing backgrounds.
- **Evidence drawer** (`Enter`): the full evidence object, IS/OOS windows, the fee basis, regime, BTC comparison,
  equity curve of paper/replay results (hand-built SVG, like `EquityCurve.tsx`: zero line always drawn, full
  drawdown in range), recent signals, and the gate's reasons.

### 3.3 Strategy evidence columns

`ID · FAMILY · STATE · GATE · n (IS/OOS) · WR (p*) · EXP NET · EXP GROSS · PF NET · DSR (trials) · OOS · vs BTC B&H ·
REGIME · SIGNALS 24h · LAST FIRE · DATA AGE`. Anything the feed sends as `null` renders `UNKNOWN`.

## 4. Data contract (to be built in T5.1)

### 4.1 Transport and envelope

- **Transport: SSE over HTTP** (`GET /v1/stream`), JSON over REST for snapshots. Why not WebSocket: the flow is
  one-way (server → terminal), SSE reconnects and resumes with `Last-Event-ID` natively in the browser's `EventSource`,
  and FastAPI 0.141.1 already provides `EventSourceResponse` (§0). One multiplexed stream carries every event type,
  so the connection count doesn't grow with panels.
- **Bind and access**: the feed listens on `127.0.0.1` only, `GET` routes only, no auth (local, read-only).
  CORS allows `http://localhost:3000` only. There is no write endpoint to protect.
- **SSE framing**: `event:` = the envelope `type`; `id:` = the envelope `seq`; `retry: 2000`; data = the envelope JSON.

Envelope (every REST item and every SSE event):

```json
{
  "v": 1,
  "type": "signal",
  "seq": 1204331,
  "ts_emit_ms": 1790431387123,
  "ts_event_ms": 1790431387001,
  "mode": "LIVE_PAPER",
  "simulated": true,
  "run_id": "live-2026-09-26",
  "data": { }
}
```

| Field | Rule |
|---|---|
| `v` | schema major version. Client accepts exactly `1`; anything else is a CONTRACT ERROR |
| `type` | one of §4.3 |
| `seq` | strictly increasing per `run_id`; SSE `id` |
| `ts_emit_ms` | feed wall clock when emitted |
| `ts_event_ms` | market time of the event (in REPLAY: simulated time). `null` where the source has none (e.g. book quotes) |
| `mode` | `"LIVE_PAPER"` or `"REPLAY"`, and must equal the mode the client subscribed to |
| `simulated` | **must be `true`**. `false` or missing ⇒ the client drops the payload and raises CONTRACT ERROR. Real money is out of scope, so there is no rendering path for it |
| `run_id` | live: `live-<date>`; replay: the replay run id from T3.0 |

The client validates with hand-written type guards (no schema library: that would be a dependency), in
`lib/feed-types.ts`. The Python side publishes JSON Schema files under `docs/feed/schema/v1/*.json` plus one
fixture per event type under `tests/loop/fixtures/feed/` (T5.1a); the front end copies the fixtures and its guards
must accept every fixture and reject the negative fixtures (`simulated:false`, wrong `mode`, `v:2`).

### 4.2 REST endpoints (all `GET`, all JSON, all enveloped or lists of envelopes)

| Endpoint | Returns |
|---|---|
| `/v1/health` | `{status, uptime_s, components:{ingest, scanner, paper_engine, recorder}}` |
| `/v1/ping` | `{ts_server_ms}`; tiny, for RTT and clock-offset estimation |
| `/v1/meta` | `hello` payload (§4.3) without a stream |
| `/v1/snapshot?mode=&run_id=` | `{seq, quotes[], positions[], signals[last 200], strategy_counts, fee_model}`; `seq` is where the stream should resume |
| `/v1/strategies?gate=&family=&symbol=&q=&sort=&dir=&cursor=&limit=` | `{items: strategy_status[], next_cursor, total, counts_by_gate}` |
| `/v1/strategies/{id}` | full evidence + `equity[]` + recent signals |
| `/v1/signals?since_seq=&strategy_id=&symbol=&limit=` | signal envelopes |
| `/v1/positions?state=open\|closed&since_ms=` | position envelopes |
| `/v1/fills?since_seq=&limit=` | paper_fill envelopes |
| `/v1/candles?symbol=&interval=&from_ms=&to_ms=` | candles from the recorder (LIVE_PAPER) or history (REPLAY) |
| `/v1/replay/runs` | `[{run_id, from_ms, to_ms, strategies, status, holdout_excluded}]` |
| `/v1/stream?mode=&run_id=&symbols=&topics=` | SSE (§4.3). `symbols` limits `candle` events to the charted symbol(s) |

**Resume and resync.** The feed keeps a ring buffer of recent envelopes per `run_id` (size set in T5.1c from
measured rates). On reconnect with `Last-Event-ID` inside the buffer, it replays the missed events; outside it, it sends
`resync` and the client re-fetches `/v1/snapshot`. The client never guesses what it missed.

### 4.3 Event types and `data` schemas

Types are shown as TypeScript-style shapes; `| null` means the feed may not know it, and the UI renders `UNKNOWN`.
Percentages are percent units (`0.21` = 0.21 %); basis points are named `*_bp`; times are epoch ms UTC.

**`hello`** (first event on every connection)
```
{ server_version: string, schema: 1, mode, run_id, universe: string[],
  fee_model: { source: "measured" | "VIP0_scenario" | "repo_assumption", taker_pct: number, maker_pct: number,
               slippage_bp: number | null, spread_source: "measured" | "unknown" },
  thresholds: { min_trades: number, dsr_min: number }, replay: null | { from_ms, to_ms, speed: number } }
```

**`heartbeat`** (1 Hz)
```
{ uptime_s: number, seq: number, clients: number, dropped_total: number,
  components: { ingest: "ok"|"degraded"|"down", scanner: …, paper_engine: …, recorder: … },
  latency_ms: { exch_to_recv_p50: number|null, exch_to_recv_p99: number|null,   // cross-clock, skew included
                recv_to_scan_p50: number|null, scan_to_emit_p50: number|null },  // same clock
  rates: { ticks_per_s: number, signals_per_min: number },
  replay: null | { sim_time_ms: number, progress: number } }
```

**`quotes`** (1 Hz, conflated batch; never per tick)
```
{ items: [ { symbol, bid: number|null, ask: number|null, last: number|null, spread_bp: number|null,
             chg_1m_pct: number|null, chg_1h_pct: number|null, msgs_per_s: number,
             quote_recv_ms: number|null, trade_ms: number|null, gap_open: boolean } ] }
```
`quote_recv_ms` is local receive time (book quotes have no exchange time, per `normalize.py`); `trade_ms` is exchange
time. Both ages are shown; neither is substituted for the other.

**`candle`** (per closed or updated 1 s kline, subscribed symbols only)
```
{ symbol, interval: "1s"|"1m"|"5m"|"1h", start_ms, open, high, low, close, volume, trades, closed: boolean }
```

**`signal`**
```
{ signal_id, strategy_id, strategy_version, symbol, side: "LONG"|"SHORT", class: "TRADEABLE"|"OBSERVED",
  ref_price: number, tp_pct: number|null, sl_pct: number|null,
  expected_move_pct: number|null, cost_rt_pct: number, p_star: number|null,
  gate_status_at_fire: "PASSED"|"FAILED"|"PENDING"|"INSUFFICIENT",
  reason: string,                       // plain language, rendered as is
  latency_ms: { tick_to_signal: number|null } }
```
`class` follows the T1.1 rule: expected move below the pair's round-trip cost ⇒ `OBSERVED`, never tradeable.

**`paper_fill`**
```
{ fill_id, signal_id, strategy_id, symbol, side: "BUY"|"SELL", intent: "OPEN"|"CLOSE",
  status: "FILLED"|"PARTIAL"|"NOT_FILLED", liquidity: "MAKER"|"TAKER",
  ref_price, fill_price: number|null, qty: number, fee_quote: number|null, fee_bp: number|null,
  spread_paid_bp: number|null, slippage_bp: number|null, modelled_latency_ms: number|null,
  model_version: string }        // the T4.1 fill model version that produced it
```

**`position`** (upsert by `position_id`)
```
{ position_id, strategy_id, symbol, side: "LONG"|"SHORT", state: "OPEN"|"CLOSED",
  qty, entry_price, mark_price: number|null, opened_ms, closed_ms: number|null,
  pnl_gross_pct: number|null, pnl_net_pct: number|null, cost_bp: number|null, cost_share: number|null,
  tp_price: number|null, sl_price: number|null, exit_reason: string|null }
```

**`strategy_status`** (batch every 5 s, changed rows only; same row shape as `/v1/strategies` items)
```
{ items: [ {
  strategy_id, family, version, params_hash, symbols: string[], timeframe,
  state: "SCANNING"|"PAUSED"|"DISABLED"|"ERROR",
  gate: { status: "PASSED"|"FAILED"|"PENDING"|"INSUFFICIENT", reasons: string[], evaluated_ms: number|null },
  evidence: {
    source: "REPLAY"|"LIVE_PAPER",
    is_window:  { from_ms, to_ms } | null,  oos_window: { from_ms, to_ms } | null,
    trades: { is: number, oos: number },
    win_rate_pct: number|null, p_star_pct: number|null, tp_pct: number|null, sl_pct: number|null, cost_rt_pct: number|null,
    expectancy_net_pct: number|null, expectancy_gross_pct: number|null, profit_factor_net: number|null,
    sharpe_oos: number|null, dsr: number|null, dsr_trials: number|null,
    oos_status: "POSITIVE"|"NEGATIVE"|"INSUFFICIENT"|"NOT_RUN",
    vs_btc: { strategy_ret_pct: number|null, btc_ret_pct: number|null, beats: boolean|null },
    regime: { trend: "trend"|"range"|null, vol: "high"|"low"|null },
    max_dd_pct: number|null },
  live: { signals_24h: number, last_signal_ms: number|null, open_positions: number, pnl_net_pct_24h: number|null }
} ] }
```
`win_rate_pct` and `p_star_pct` travel together; a row with one and not the other is a CONTRACT ERROR.

**`scan_cycle`** (per scanner cycle; the feed may sample to ≤ 1 Hz and says so with `sampled_from`)
```
{ cycle_id, started_ms, duration_ms, strategies_evaluated, symbols, signals_emitted, errors: number,
  sampled_from: number }
```

**`data_quality`**
```
{ kind: "GAP"|"RECONNECT"|"STALE_STREAM"|"CLOCK_SKEW"|"BUFFER_OVERFLOW"|"REPLAY_HOLDOUT_BLOCKED",
  symbol: string|null, stream: string|null, detail: string,
  gap: null | { from_id, to_id, missing } }         // same fields as gaps.py
```

**`resync`** `{ reason: "buffer_expired"|"run_changed"|"server_restart" }` → client re-fetches the snapshot.

Event list: `hello`, `heartbeat`, `quotes`, `candle`, `signal`, `paper_fill`, `position`, `strategy_status`,
`scan_cycle`, `data_quality`, `resync`.

### 4.4 Rates and back-pressure

| Stream content | Rate to the browser |
|---|---|
| raw ticks (≈540 msg/s measured) | **never sent** |
| `quotes` | 1 batch/s for the whole universe |
| `candle` | ≤ 1/s per subscribed symbol |
| `strategy_status` | 1 batch/5 s, changed rows only |
| `signal`, `paper_fill`, `position` | as they happen; if a burst exceeds the client queue, the feed drops `signal` events of class `OBSERVED` first, never `paper_fill`/`position`, and counts every drop in `heartbeat.dropped_total` (shown in the top bar) |

### 4.5 Latency and "ping"

| Hop | Measured by | Label on screen |
|---|---|---|
| exchange → ingest | feed: `ts_recv − trade_ms` (aggTrade/kline only) | `exch→recv (skew incl.)` |
| ingest → scanner → emit | feed, same clock | plain |
| feed → browser RTT | client: `performance.now()` around `GET /v1/ping`, every 2 s | `rtt` |
| clock offset | client: `ts_server − (t0 + t1)/2` from the same ping | `skew est` |
| emit → browser one-way | client: `now − ts_emit_ms − skew est` | `emit→ui (est.)` |

Book quotes have no exchange timestamp, so no exchange latency is ever shown for them.

## 5. The terminal's own "one rule"

> **Every number on the terminal is a field of a feed envelope that passed validation, or a count/age the client
> measured and labels as such.** No number from `ledger.json`, no recomputed evidence, no fallback value.

This mirrors `AGENTS.md` §2 for a different data source. It should be added to `AGENTS.md` in T6.2 (owner OK needed:
it's copy about facts).

## 6. Visual system

### 6.1 Principles

Cyber/terminal, but for reading, not for show: square corners, 1 px opaque grid lines, dense tabular rows, colour
only where it carries meaning, no glass, no glow, no aurora behind data. It's a working instrument.

### 6.2 Mapping onto the existing Tailwind config without breaking current pages

- **Additive only.** A new `term` colour namespace in `theme.extend.colors`; no existing token changes value. Existing
  pages don't reference `term-*`, so they can't change. This is still a token change under `AGENTS.md` §5, so it
  **needs the owner's OK** before T6.2 lands (open question 2).
- **Radius 0** by class, not by config: terminal components use Tailwind's built-in `rounded-none`; the global
  `:focus-visible { border-radius: 4px }` is overridden only inside a `.term` root (`.term :focus-visible
  { border-radius: 0; outline-offset: 0 }`). The shared `borderRadius` scale is untouched.
- **Scoped CSS** goes in `app/globals.css` under a `.term` selector in `@layer components`, because `check-tokens.py`
  scans `app/globals.css` and would not scan a separate terminal stylesheet.
- **Backdrop**: the root layout mounts `AuroraBackdrop` for every route. The terminal shell is an opaque, fixed,
  full-viewport `term-bg-0` surface; additionally one scoped rule, `body:has(.term) .aurora-blob { animation: none;
  display: none }`, stops the backdrop on this route only, so the GPU isn't blurring blobs nobody sees 24/7. (Alternative: route groups with separate root
  layouts. Cleaner, but moves every existing page into a group, which `AGENTS.md` §5 calls an architecture refactor.)
- **Token formatting must match `check-tokens.py`'s parser**: parent key at 8 spaces, children at 10 spaces, 8-digit
  hex = alpha-baked. The terminal tokens below are **6-digit opaque hex** on purpose, so `/opacity` modifiers stay
  legal and the double-alpha guard has nothing to trip on.

### 6.3 Colour tokens (proposed; WCAG 2.1 contrast computed with the relative-luminance formula)

| Token | Hex | Meaning | Contrast on `term-bg-2` |
|---|---|---|---|
| `term-bg-0` | `#05070A` | page | — |
| `term-bg-1` | `#0A0E13` | panel body | — |
| `term-bg-2` | `#0F151C` | panel title, table header, selected row | — |
| `term-grid` | `#1C2530` | 1 px panel and row rules | 1.19 (decorative) |
| `term-grid-strong` | `#2A3645` | focused panel border | 1.50 (decorative; focus also uses cyan) |
| `term-cyan` | `#3FD7EC` | focus, live/OK state, changed-row rule | 10.61 |
| `term-amber` | `#F5B83D` | STALE, WARN, SIMULATED badge | 10.32 |
| `term-violet` | `#B69CFF` | REPLAY mode badge and hatch | 8.03 |
| `term-error` | `#FF5A5F` | CONTRACT ERROR, component down | 6.01 |
| reuse `profit` | `#2FD98B` | positive P&L / above p* | 9.98 |
| reuse `loss` | `#FF7183` | negative P&L / below p* | 6.94 |
| reuse `ink` / `ink-muted` / `ink-ghost` | existing | text; `ink-ghost` = stale and FAILED rows | 16.77 / 10.28 / 4.90 |
| `term-cb-up` | `#5AA9FF` | colour-blind palette, positive | 7.47 |
| `term-cb-down` | `#FF9F40` | colour-blind palette, negative | 8.99 |

Rules:
- **Colour never carries meaning alone.** Every signed number carries an explicit `+`/`−`; direction also has a glyph
  (`▲`/`▼`); states carry a word (`STALE`, `LOST`, `FAILED`). The `c` key swaps profit/loss for the blue/orange pair,
  which stays distinguishable for red-green colour blindness.
- Stale text uses `ink-ghost` (4.90:1 on `term-bg-2`, AA for small text). A darker "dimmer" grey was rejected: the
  candidate `#6B7582` measured 3.93:1 and fails AA.
- Selected rows use `term-bg-2` plus a cyan 1 px outline, not a lighter fill: on a lighter `#16202A` fill,
  `ink-ghost` drops to 4.40:1.
- `term-error` is reserved for the system being wrong. It's never used for a losing trade (that's `loss`), so a red
  cell always means money and an error tag always says `ERR`/`CONTRACT`.
- Measured aside: the existing `profit`/`loss` pair computes to a relative-luminance ratio of 1.50 with the WCAG
  formula; the config comment says 1.19. The method behind 1.19 isn't stated. Not changed here; flagged for the owner.

### 6.4 Typography and density

- Fonts already loaded: JetBrains Mono (`font-mono`) and Inter (`font-sans`). No new font.
- **Mono** for identifiers, symbols, strategy ids, timestamps, panel titles, the tape's log lines and the command line.
- **Numbers (prices, P&L, rates) in Inter with tabular figures** (`.tnum`, already defined), keeping the site doctrine
  "monospace never for money". The columns still align because the figures are tabular. (Owner may prefer all-mono for
  the terminal look; open question 4.)
- Sizes: body 12 px (`text-xs`), labels 11 px (`text-micro`, uppercase, positive tracking like `.eyebrow`). Row height
  20 px; panel title 22 px; 8 px panel padding; 1 px rules between rows every row (no zebra striping).

### 6.5 Motion rules

- **Values change instantly.** No count-ups, no tweened prices, no per-second flashing. `anime.js` isn't used by the
  terminal at all.
- Allowed transitions (CSS only, 200 ms, the existing `standard` curve): a state change (LIVE → STALE → LOST), a new
  tape row's background settling from `term-bg-2` to `term-bg-1`, a changed strategy row's 1 px cyan rule fading after
  2 s.
- Nothing loops. The feed status dot doesn't pulse; its word changes.
- `prefers-reduced-motion`: the global rule in `globals.css` already reduces every duration; the terminal adds nothing
  that depends on motion to be understood.
- The tape doesn't move under the pointer: while it's hovered or focused, new rows queue and a `+N new` counter shows.

## 7. Front-end architecture (inside the existing repo's conventions)

- **Route** `app/terminal/page.tsx` (server component, `robots: { index: false }`, not linked from `SiteHeader`).
  It passes only serializable props (the feed URL string) into one client root, so `check-boundary.py` has no
  function prop to flag.
- **Inert without a feed.** The feed URL comes from `NEXT_PUBLIC_TERMINAL_FEED_URL`. When unset (e.g. the Vercel
  build), the page renders a static line saying the terminal is a local operator tool and no feed is configured; it
  never tries `localhost` from a visitor's browser.
- **Feed client** `lib/feed-client.ts`: one `EventSource`, a snapshot fetch, resume/resync, heartbeat watchdog;
  events go into a small external store read with React's `useSyncExternalStore`, with rendering coalesced to one
  pass per animation frame (tables ≤ 4 Hz). No state library (no new dependency).
- **Types and guards** `lib/feed-types.ts`: TypeScript types for §4 plus runtime guards. Parsed values are narrowed by
  guards, never by `as number` casts (`check-unsafe-cast.py`).
- **Chart**: reuse the `ChartSlot` pattern (`next/dynamic`, `ssr:false`) and the same `lightweight-charts` calls
  already in the repo. Candles come **from the feed**, not browser-direct Binance, so markers sit on the prices the
  scanner actually saw, and REPLAY works the same way.
- **Components** named `components/Term*.tsx`, flat. `check-tokens.py` globs `components/*.tsx` (not subfolders), so a
  `components/terminal/` folder would silently escape the double-alpha guard; flat names keep every terminal file inside
  guard coverage without editing a guard.
- **Guard compatibility (would otherwise break the prebuild):**
  - `check-fields.py` checks any local named `s`, `sig`, `signal`, `o`, `outcome`, `stats`, `led`, `execution` against
    the ledger interfaces in `lib/api.ts`. Feed objects **must not use those names** (use `ev`, `fs`, `pos`, `strat`),
    or every feed field read becomes a false "field not on interface" failure.
  - `check-jsx.py` / `check-imports.py`: import every hook and component explicitly.
  - `check-setstate-shape.py`: no aliasing of state setters (the store is external anyway).
  - `check-boundary.py`: server page → client root passes strings/numbers only.
  - `check-tokens.py`: terminal tokens are opaque 6-digit hex; no `/opacity` on alpha-baked `line-*` tokens.

### 7.1 Performance budget (targets; verified in T6.2/T6.3, not measured yet)

| Budget | Target | How it's met |
|---|---|---|
| Main-thread work per second of feed | ≤ 50 ms/s (≤ 5 %) at 15 symbols, 3 000 strategies, 10 signals/s | server conflation (§4.4), rAF-coalesced renders, virtualization |
| Frame time while updating | no long task > 50 ms | tables ≤ 4 Hz, no layout thrash (fixed row heights) |
| DOM size | < 3 000 nodes | only visible rows rendered; tape keeps 200 rows in DOM, 2 000 in memory |
| Memory after 24 h | flat (no growth trend) | ring buffers everywhere; closed positions paged from REST |
| Terminal JS excluding the chart chunk | ≤ 60 KB gzipped of new code | no new dependencies; chart chunk lazy as today |
| Time to first data | ≤ 1 s after load on localhost | one snapshot request, then stream |

The 24 h memory check is part of T6.3's acceptance (a soak run with the browser's memory panel, screenshot attached).

## 8. Options considered

| Option | Why not |
|---|---|
| WebSocket instead of SSE | two-way isn't needed; SSE gives resume via `Last-Event-ID` for free and FastAPI 0.141.1 supports it without a new dep |
| Stream raw ticks to the browser | 540 msg/s measured; the operator can't read it and the main thread pays for it |
| A virtualization library / state library / schema library | each is a new runtime dependency, which the front-end repo treats as a product decision; fixed-height windowing and guards are small |
| Browser-direct Binance for the terminal chart (as the site does) | markers would sit on prices the scanner may not have seen; doesn't work for REPLAY |
| Separate repo/app for the terminal | the task and roadmap put it in `livresignals`; sharing fonts and tokens keeps one design language. Revisit if the public build ever gets heavier because of it |
| Route-group root layouts to drop the aurora | cleaner isolation, but moves every existing page; treated as an architecture refactor |

## 9. Pre-mortem: it's 3 months later and the terminal failed. Why?

1. **It became a slot machine.** Flashing tape, win rates first, green everywhere; the owner trusted what looked busy.
   *Mitigation:* §3.1 rules are component types, default sort is DSR, survivors-only default, no motion on values.
2. **A REPLAY screenshot got shared as live results.** *Mitigation:* one mode per connection, violet hatch + badge in
   every panel title, `run_id` visible.
3. **The feed died silently and the screen kept looking live** (EventSource reconnect loop, laptop sleep).
   *Mitigation:* heartbeat watchdog (3 s STALE, 10 s LOST), ages as text, frozen-at timestamp.
4. **The browser melted** at thousands of strategies or a signal storm. *Mitigation:* server conflation, 5 s strategy
   deltas, drop-OBSERVED-first with visible counters, virtualization, rAF coalescing, a soak test.
5. **The prebuild broke on Vercel** because of a guard nobody ran: a feed object named `signal` tripping
   `check-fields.py`, or a function prop across the boundary. *Mitigation:* §7 guard rules, run `npm run prebuild`
   (the guards need only Python) on every T6.x PR.
6. **Contract drift** between Python and TypeScript: a renamed field renders `UNKNOWN` everywhere, or worse, a stale
   field keeps rendering. *Mitigation:* one fixture set shared by both sides, `v` checked, unknown major = CONTRACT
   ERROR, negative fixtures.
7. **The terminal leaked onto the public site** and visitors saw a broken page or it pointed at `localhost`.
   *Mitigation:* inert without the env var, `noindex`, not linked.
8. **Latency numbers lied** because of clock skew. *Mitigation:* cross-clock hops labelled, skew estimated and shown.
9. **Scope creep to buttons** ("just add a close-position key"). *Mitigation:* the feed has no write route; adding one
   is a Phase 8, owner-gated decision, not a UI tweak.
10. **Fee basis silently wrong** (repo assumption shown as if measured). *Mitigation:* `fee_model.source` on every
    screen that shows net figures.
