# T3.0 + T3.1 · Design: historical replay harness and the one strategy interface

Status: design for T3.1 (replay core) and T3.2 (scanner). **Paper/research only.** Nothing here places, sizes
or manages a real order. Every number the harness produces is labelled `mode: "REPLAY"`.

## Goal

The owner's idea (2026-09-26): replay all history, bar by bar, from the first candle to the last, through the
**same** strategy and paper-execution code that will run on live ticks, as if trading in real time. A replay is a
simulation of the live loop, not a separate backtester with its own rules.

## Facts (measured on this machine, 2026-09-26)

- Data on disk (T2.6, read-only for replay): `data/local/history/monthly/klines_1m/<SYM>/<SYM>-1m-YYYY-MM.zip`,
  15 coins, one CSV per zip, **no header row**, 12 columns: open_time, open, high, low, close, volume, close_time,
  quote_volume, trades, taker_buy_base, taker_buy_quote, ignore. BTCUSDT and ETHUSDT: 109 months each, 2017-08 → 2026-08.
- **Timestamp units change.** `BTCUSDT-1m-2024-12.csv` opens with `1733011200000` (ms);
  `BTCUSDT-1m-2025-01.csv` opens with `1735689600000000` (µs); close_time likewise (`…59999` vs `…59999999`).
  The loader must detect units per value by magnitude, never by file date.
- First BTC bar: open_time 1502942400000 = 2017-08-17 04:00 UTC. Early months have 0-volume bars and gaps
  (exchange outages); gaps are data, never interpolated.
- Size: a month of 1m bars is ~44,640 rows (~3 MB CSV). Streaming one row at a time keeps memory flat.
- Last complete month on disk: 2026-08. Daily 1s klines and aggTrades exist for the last 30 days only (T2.5);
  the replay core uses 1m klines; 1s/aggTrades replay is a later task.
- Live ticks: `trading.stream.normalize.Tick(kind="kline", …, data={interval, start_ms, open, high, low, close,
  volume, trades, closed})`. A closed live 1m kline carries the same fields as a history row.

## Design

### 1. Bar: the unit both paths share

```python
@dataclass(frozen=True, slots=True)
class Bar:
    symbol: str
    interval: str        # "1m", "1h", "1d", ...
    open_ms: int         # always milliseconds (normalised on load)
    end_ms: int          # open_ms + interval length: the instant the bar becomes KNOWN
    open: float; high: float; low: float; close: float
    volume: float; quote_volume: float; trades: int; taker_buy_base: float
```

`end_ms` (not Binance's `close_time = end - 1`) is the time the bar exists. The rule "ctx sees only data with
time <= now" is stated against `end_ms`.

Two adapters produce `Bar`s: `loader.iter_klines(path)` (history zip) and, in T3.2, `bar_from_tick(Tick)` for
closed live klines. Everything downstream is the same code.

### 2. Strategy interface (identical for live and replay)

```python
class Strategy(Protocol):
    name: str
    params: dict              # frozen at construction; part of the trial identity
    intervals: tuple[str, ...]  # bar intervals it wants, e.g. ("1d",)
    def on_bar(self, bar: Bar, ctx: Context) -> list[Signal]: ...
```

`Context` is the only window a strategy has on the world:

| member | returns |
|---|---|
| `ctx.now_ms` | the clock (replay clock, or wall clock live) |
| `ctx.history(symbol, interval, n)` | the last `n` **closed** bars with `end_ms <= now_ms`, oldest first, as a tuple |
| `ctx.last(symbol, interval)` | the latest closed bar, or `None` |
| `ctx.position(symbol)` | current paper position (qty, entry) from the account, read-only |
| `ctx.bar_at(symbol, interval, end_ms)` | that bar if `end_ms <= now_ms`; **raises `LookAheadError` otherwise** |

A strategy holds no reference to the data source, the replayer, or the account object itself.

### 3. No-look-ahead guarantee (hard, not a convention)

1. **Structural.** The loader is a generator; bars not yet yielded are not in memory. The `BarStore` behind `ctx` is
   append-only and only receives a bar when the clock reaches its `end_ms`.
2. **Checked on every read.** `ctx` asserts every bar it returns has `end_ms <= now_ms`, and any request naming a
   future time raises `LookAheadError`. This is always on (it is cheap), not a debug flag.
3. **Clock is monotonic.** `ReplayClock.advance(t)` raises if `t < now`.
4. **Execution cannot use the signal bar.** A signal emitted at `now` is filled at the **open of the next 1m bar**
   of that symbol (`open_ms >= signal ts`), never at the close that produced it. Fills assert this.
5. **Resampling never leaks a partial bar.** A 1d bar is emitted only when its period has ended on the clock; if
   the last minute is missing, it is emitted at the first later clock step, still with only in-period minutes.
6. **Same-instant fairness.** At one clock step, all bars ending at that instant (every symbol) enter the store
   *before* any strategy is called, so ETH's strategy call sees BTC's bar for the same day, and nothing later.

**Canary tests** (must fail loudly if any of the above breaks): a cheating strategy that calls
`ctx.bar_at(..., now + 1 day)` must raise `LookAheadError`; a strategy that records every `ctx.history()` result
must never see `end_ms > now_ms`; a fill must never be priced from a bar that opened before the signal.

### 4. Replay clock and loop

```
for group of 1m bars with the same open_ms T (heap-merged across symbols):
    clock.advance(T)                  # fills: pending orders fill at these bars' OPEN
    clock.advance(T + 60s)            # closes known
    store 1m bars; feed resamplers; collect bars whose period ended  <= now
    store all emitted bars, then call strategies (symbol order, deterministic)
    signals -> pending orders for the next step; mark equity to market at the 1m closes
```

Live (T3.2) runs the same loop body, driven by closed live klines and the wall clock.

### 5. Signal event schema

```json
{"mode": "REPLAY", "type": "signal", "ts": "2021-01-02T00:00:00Z", "ts_ms": 1609545600000,
 "payload": {"id": "trend_sma50:ETHUSDT:1609545600000", "strategy": "trend_sma50",
             "params": {"sma": 50, "btc_sma": 50}, "symbol": "ETHUSDT", "side": "L",
             "action": "open" | "close", "reason": "close>sma50 & btc>sma50", "ref_price": 729.1,
             "interval": "1d", "run_id": "..."}}
```

Fills and closes use the live ledger's record types and field names (`signal_ledger.py`: `type` = `signal` /
`close`, payload `id, symbol, side, entry, opened, exit, ret, why, pnl`), plus `mode: "REPLAY"`, `fee`,
`gross_ret`, `net_ret`. Replay records go to `data/local/replay/<run_id>/events.jsonl` (gitignored) and are
**never appended to the real ledger** (`signal-ledger.jsonl` is on the no-touch list and has a hash chain that
must never contain simulated records).

### 6. Paper execution and a shared account

- One shared account per run (starting equity 1000 USDT, a scale-free choice; returns are reported, not dollars).
- Long-only spot, no leverage. `slots` positions max; a new position gets `min(cash, equity / slots)` at entry.
- Fill price: `next 1m open × (1 ± (spread_bps/2 + slippage_bps)/1e4)` (buys pay up, sells receive less).
- Fee: `fee_rate × notional` per side, default **0.001 (VIP 0, 0.10%/side)**, configurable. The real account rate
  is UNKNOWN (fees-and-breakeven.md); spread per pair is UNKNOWN until T2.3 measures it, so `spread_bps` and
  `slippage_bps` are stated assumptions in every report.
- **Gross** = the same run with fee, spread and slippage set to 0. **Net** = with costs. Both always printed.
- Equity is marked to market at every 1m close, so max drawdown is intraday, not end-of-day.

### 7. Windows: walk-forward and the untouched holdout

- **Holdout** = the last 6 complete months on disk (today: 2026-03-01 → 2026-09-01). The harness refuses to replay
  into it unless `--open-holdout` is passed, and that flag is for the final gate of a finished strategy only.
  No parameter may be chosen after looking at holdout output.
- **Walk-forward** (`windows.walk_forward(start, end, fit_months, trade_months)`): fit on `[t-fit, t)`, trade
  `[t, t+trade)`, roll by `trade`. Fixed-parameter strategies have nothing to fit; they still report per trade window.
  Fitting strategies (T3.5) receive only the fit window's bars.
- **IS/OOS** is a chronological split inside the non-holdout range.
- **Trials.** Every replay of a `(strategy, params)` on non-holdout data appends one line to
  `data/local/replay/trials.jsonl`. T3.3's Deflated Sharpe uses that count as the number of trials; a variant
  that was looked at and discarded still counts.

### 8. Benchmark and regime (required by the audit gate)

- **BTC buy-and-hold** over the same trade window, bought at the first 1m open with the same cost model; gross and net.
- **Regime of the window**, computed from BTC daily closes: total return, annualised volatility of daily returns,
  share of days above the 200-day SMA. Label: `bull` if total return > +20%, `bear` if < −20%, else `range`;
  `high-vol` if annualised vol > 60%, else `low-vol`. The thresholds are arbitrary and stated; the raw numbers are
  always printed next to the label.

### 9. The first plugin: trend follower baseline (read-only re-implementation)

Rule (from `strategy-inventory.md`; `scripts/trend_follower.py` is neither imported nor edited):
on each **daily** bar (resampled from 1m, UTC days) of coin X,
- **enter long** if `close(X) > SMA50(X)` and `close(BTC) > SMA50(BTC)` and X is not held;
- **exit** if `close(X) < SMA50(X)`.

Known differences from the live script, stated rather than hidden: the live script also has a −15% hard stop, runs
every 4 hours, and caps 3 positions at $5.5 each. The port uses daily closes only and no hard stop.

## Options considered

| Option | Why not |
|---|---|
| Vectorised backtest (numpy arrays over whole history) | Fast, but a different code path from live, and look-ahead is easy (shift errors). Replay must be the live loop |
| Load a month into numpy then iterate | Saves little; the row loop is the cost either way. Kept as an optimisation if speed matters |
| pandas resample | pandas is not installed; one dependency for one resample isn't worth it |
| Fill at signal bar close | Classic look-ahead: the close is only known when the bar is over. Next 1m open is the earliest honest price |
| Write REPLAY records into the real ledger with a flag | The ledger is no-touch and hash-chained; mixing simulated and real records is the failure this project exists to avoid |

## Pre-mortem: it is 3 months later and this failed. Why?

1. **Look-ahead crept in through a side door**, e.g. a strategy read a file directly or a resampler emitted a partial
   day. *Guard:* canaries in CI; strategies get only `ctx`; resampler tests with a missing last minute.
2. **µs/ms confusion** put 2025+ bars in the year 57000 or collapsed them. *Guard:* magnitude detection with tests on
   both units and a month-boundary test.
3. **Holdout contamination**: someone ran the holdout, disliked it, changed a parameter. *Guard:* `--open-holdout`
   flag, every run written to `trials.jsonl` with its window, so the log shows it.
4. **Costs too low**: spread assumptions flattered a high-turnover variant. *Guard:* gross/net always both printed;
   stress scenario; T2.3 replaces assumptions with measured spreads.
5. **Survivorship**: the 15 coins are today's survivors. *Guard:* stated in every report; a delisted-coin universe
   is out of scope until data exists.
6. **Live and replay drifted apart** because T3.2 added a live-only branch. *Guard:* one loop body; a test feeds the
   same bars through the live adapter and the replay adapter and asserts identical signals.
7. **Replay mistaken for evidence of edge.** *Guard:* every output says REPLAY and "research, not evidence of edge";
   the T3.3 gate (DSR over all trials, BTC benchmark, regime) decides, not a single replay.

## Test plan (tests/loop/test_replay.py, written first)

- loader: ms rows and µs rows both normalise to ms; a header row, if present, is skipped; streaming yields rows lazily.
- resampler: 1m → 1d aggregates OHLCV correctly; a day with a missing last minute emits only in-period data, never early.
- clock: monotonic; moving backwards raises.
- context: `history` never returns `end_ms > now`; `bar_at(future)` raises `LookAheadError` (**canary**).
- full replay with a cheating strategy raises `LookAheadError` (**canary**); a recording strategy never observes the future.
- execution: fills at next 1m open, never before the signal; fees and spread charged per side; gross == net when costs are 0.
- shared account: two symbols share cash; equity/slots sizing; no position exceeds cash.
- trend plugin: enters only when both coin and BTC are above SMA50; exits when coin < SMA50; warmup emits nothing.
- windows: walk-forward windows tile the range; holdout is excluded unless opened.
- safety: `trading.replay` imports no ccxt / `trading.exchange` (import-graph test).
