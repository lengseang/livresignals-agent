# T0.23 — the tail must sit beside the mean, in every reader of a book

**Status:** reader/display change only. No rule, gate, sizing path or order path
reads these numbers. Branch `loop/T0.23-tail-beside-the-mean`, cut from
`loop/T0.22-trend-tail-probe`.

## Problem

Two shipped readers report a book's *arithmetic mean* return per trade as the
headline and print nothing about the shape of the distribution around it:

```text
scripts/expectancy_vs_fee.py:11 (module docstring) + main()
  trend_follower (REAL $)  n=212  avg gross +1.210%  net/trade +1.050%
                           t=+1.68  win 21.7%  -> "alive, unproven"

scripts/per_symbol_net.py  (ALL BOOKS COMBINED and per-row columns)
  net = mean(rs) - FEE_RT        (no median, no delete-1)
```

On the real trend book that mean is **+1.050%/trade** while the median trade
loses **-1.324%** and the mean goes to **+0.003%** when the single largest row
is deleted (T0.22, `research/_trend_tail_concentration.py`). The number is not
*false* — it is a true statement about the right tail — but printed alone it is
read as a statement about the typical trade, and it is the opposite of that.
A trend-follower is *supposed* to have this shape; the defect is that the
reader does not say so, so a good week's worth of tail gets quoted as a
strategy's expectancy.

This is rule 2 in the loop contract: a plausible wrong number is worse than an
honest one. The mean is not wrong, but a mean with no tail beside it is a
number that will be misread by anyone who does not already know the shape.

## Options

- **A. Replace the mean with the median.** Wrong: the mean is the quantity that
  compounds over a trend book's tail; discarding it would hide the edge instead
  of describing it. Two errors do not make a right.
- **B. Add a warning word when skew is high, no numbers.** Subjective — "high"
  would be a threshold nobody can audit, and the reader still cannot see the
  size of the effect.
- **C. (chosen) Print `median NET` and `delete-1 mean NET` in the same row /
  block as the mean, plus a one-line sign-flip note when deleting the single
  best trade turns the mean non-positive.** All quantities are computed from
  the same `rs` list the row already uses (same population, same fee basis), so
  the reader cannot quote three numbers drawn from three populations.

## Choice, and the exact quantities

For a list of per-trade returns `rs` (fractions for `expectancy_vs_fee`,
percents for `per_symbol_net` — each keeps its own unit), with
`net(x) = x - fee`:

- `mean_net`   = mean(rs) − fee            (already printed; unchanged)
- `median_net` = median(rs) − fee          (NEW)
- `delete1_net`= mean(rs minus its single largest element) − fee   (NEW, n≥2)

Skew indicator (NEW, wording only): when `mean_net > 0 >= delete1_net`, the row
gets a one-line note that the positive mean rests on ≤1 trade. When
`mean_net <= 0 < median_net` no note (the mean understates; harmless). The note
is *derived from the printed numbers*, so it can never contradict them.

**Median definition:** for even `n`, the arithmetic mean of the two central
values (the standard definition), documented in the helper so a reader cannot
guess which one was used.

**Delete-1:** drops exactly one element — the maximum. It is not the "delete
5%" rule; that belongs in a research probe, not a per-row reader. Deleting one
is the smallest edit that answers "is this number one trade?".

## Where it goes

- `scripts/expectancy_vs_fee.py`: add `median()`, `delete_best_mean()` and a
  `tail_note()` helper (pure, module-level, importable — following the T0.10
  precedent of wrapping the report in `main()`). Print `median NET` and
  `delete-1` columns for every book row, and a `tail` block under the
  DIAGNOSIS for any book where the note fires.
- `scripts/per_symbol_net.py`: same two helpers (imported from
  `expectancy_vs_fee`, so there is ONE definition — a second copy is how two
  readers come to disagree), printed in the per-symbol row.

The helpers live in `expectancy_vs_fee.py` and `per_symbol_net.py` imports
them. `per_symbol_net.py` already inserts `scripts/` on `sys.path`.

## Failure modes (adversarial self-review)

1. *"It is 3 months later and this failed: why?"* — The columns were added to
   the header but a book with a single trade crashed `delete_best_mean` on an
   empty list, taking the whole report down. **Guard:** `delete_best_mean`
   returns `None` for `n < 2`; the cell prints `n/a`, never a number.
2. *Two readers drift* — `per_symbol_net` copies the helper, one of them later
   changes the median convention. **Guard:** tests assert both readers produce the
   identical `median_net`/`delete1_net` for the same input, and that they resolve
   to the same source line in `expectancy_vs_fee.py` (no redefinition).
3. *The note is a knife-edge.* **This actually happened while building it.** The
   note fires only when `delete1_net <= 0`. On 2026-11-12 the real trend book's
   delete-1 was **+0.003% at n=212** (T0.22) and became **+0.697% at n=213** when
   one +10.7% trade landed — so the note *stopped firing* while the median and
   the concentration were unchanged. A boolean gate on one borderline row is not
   a property of the book. **Therefore the primary output is the two COLUMNS**
   (median and delete-1 printed on every row, unconditionally); the note is only
   a highlight for the clearest case (delete-1 ≤ 0) and is never the only signal.
   The columns cannot be "turned off" by a single trade.
4. *A NaN / non-finite return poisons median or mean.* Existing `to_rates`
   only admits `int`/`float`; NaN is a float. **Guard:** helpers drop
   non-finite values before computing, and the test suite pins that behaviour.
5. *The change alters a verdict.* It must not: `v` (the verdict string) is
   computed exactly as before from `mean_net` and `t`. Pinned by a test that a
   book which read "DEAD — no edge" before still reads it, with the tail
   columns beside it and no note.

## What was measured while building it (and the correction it forced)

The T0.22 journal records `delete 1 -> +0.650%`, `delete 3 -> +0.295%`,
`delete 5 -> +0.003%` (all NET). Recomputing today at n=213 gives NET
`+0.697 / +0.344 / +0.054` (gross `+0.856 / +0.503 / +0.214`). Rather than
assume "the journal was wrong", the exact T0.22 snapshot was reconstructed:
dropping the single row appended at `2026-11-12T12:10:13Z` (PEPE, +10.7%)
reproduces T0.22's five delete-k numbers to within 0.001 pp. **T0.22 was
correct at its own timestamp.** The book has since gained one trade, and that is
enough to move delete-5 from +0.003% to +0.054%. This is recorded because it is exactly the fragility the note is
guarding against, and because a future reader comparing the T0.22 journal to a
fresh run must not conclude the probe was wrong.

## Test plan (`tests/loop/test_tail_beside_the_mean.py`)

1. `median` odd n → central value; even n → mean of the two central values.
2. `median` of a single element → that element; of empty → `None`.
3. `delete_best_mean` drops exactly the max, not the min; `n<2` → `None`.
4. Non-finite inputs are excluded (NaN/inf in → finite out).
5. `tail_note` fires in the exact real-book shape: mean_net > 0, delete1_net ≤ 0.
6. `tail_note` silent when delete-1 stays > 0 (a broad edge).
7. `tail_note` silent when the mean is already ≤ 0.
8. **End-to-end render:** a fixture book with one large winner renders a row
   whose `median NET` is negative while `net/trade` is positive, and a tail
   note appears — this is the T0.22 real-book shape, so the reader is proven
   to *show* it.
9. Both readers agree: same input → identical median/delete-1.
10. Verdict string unchanged by the change (control).
11. **Columns are unconditional:** a book whose delete-1 stays positive gets
    NO note but STILL shows a negative median (the knife-edge lesson, f-mode 3).
12. Mutation: make `delete_best_mean` drop the min instead → 7 tests must red.

## What this does NOT do

- It does not change any verdict, threshold, gate, size or order. It is a

- It does not edit `check-books.py` (no-touch list). T0.13 stays owner-gated.
- It does not fix the NEAR row (E18) — that needs exchange fill history.
