# T3.3b · Design: the gate counts distinct parameter sets as trials

Status: implemented in `src/trading/replay/gate.py` (`trial_key`, `distinct_trials`). Research only.

## Problem

The Deflated Sharpe Ratio deflates a result by the number of independent strategy configurations that were
tried (N). The T3.3 gate set N = the number of lines in `data/local/replay/trials.jsonl`. On 2026-09-26 that log
held 5 runs: `trend_sma` with sma 50/100/150/200 on the flat cost model, and sma 50 **again** on the measured
paper broker (`--broker paper`). The fifth line re-prices the same selection with a different fill model; it
is not a new hypothesis. Counting it inflates N and, with it, SR0, so the gate was stricter than the method
says, and would grow stricter every time a cost model is refined, which rewards not re-checking costs.

## Rule

A trial is a distinct `trial_key`:

    strategy + params (key-order free) + symbols (order free) + trade_from + to

Not part of the key: `run_id`, `broker`, costs / fill-model settings, `holdout_opened`, `mode`.

- Same strategy + params + universe + window, other broker or costs: **same trial**.
- Different params: new trial.
- Different universe or window: new trial. These are researcher choices too; counting them keeps N on the
  conservative side (a larger N only makes the gate harder to pass).
- Discarded variants still count. The raw log is append-only and is never rewritten or de-duplicated on disk;
  the grouping is recomputed on each gate run and written into `gate.json` (`checks.dsr.trials`,
  `n_logged_runs`, `trial_rule`).

V[SR_n] takes one Sharpe per distinct trial: the gated run's own for its group; for other groups, the latest
logged run of the group whose Sharpe is recoverable (the latest reflects the current cost model).

## Options considered

1. Keep counting runs (status quo): over-counts on every cost re-run; rejected.
2. Key on `(strategy, params)` only: a universe or window change would silently not count; rejected as
   anti-conservative.
3. Chosen: the key above.

## Failure modes (pre-mortem)

- A parameter that is not stored in `params` (e.g. a hard-coded constant changed between runs) would make two
  different hypotheses share a key. Mitigation: plugins must put every rule constant in `params`
  (`trend_real` does, T3.3c).
- Old log lines without `symbols` / window fields key as `null` for those fields; they still group correctly
  with each other.
- N still excludes choices made before logging (e.g. SMA50 picked by the live script's author); the gate's
  caveat says N is a lower bound.

## Tests

`tests/loop/test_gate.py`: key ignores broker/run_id/holdout flag and param/symbol order; key changes with
params, strategy, universe, window; the real 5-line log shape gives N = 4; the CLI counts 2 distinct sets from
3 runs, takes one Sharpe per set, and leaves `trials.jsonl` byte-identical.
