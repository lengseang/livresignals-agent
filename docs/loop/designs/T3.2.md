# T3.2 · Design: live scanner over the same strategy interface as replay

Status: implemented on `loop/T3.2-live-scanner` (stacked on `loop/T3.1-replay-core`). **Paper only.** The scanner
emits simulated signal records; it has no order path and imports no exchange client.

## Problem

T3.0 promised that "live runs the same loop body" as replay (pre-mortem #6: live and replay drift apart through a
live-only branch). T3.2 has to turn a live tick stream into the exact bar sequence replay consumes, and run the
same strategies on it, without a second implementation of the strategy loop.

## Choice

1. **One loop body.** `trading.replay.engine.replay()` was split into `LoopCore.step(t, closed, opens)` (closes →
   resample → decide → record → fills, unchanged) and a thin driver that heap-merges history. The scanner drives
   the same `LoopCore`. There is no scanner copy of Context, BarStore, resampling or paper fills.
2. **Bar builder** (`scanner/bars.py`): closed `kline_1s` ticks (default) or `aggTrade` ticks → 1m `Bar`s.
   - A 1m kline's open is the minute's first *trade*. Binance's 1s stream (and its 1s history files: 6,732 of
     86,400 rows on BTCUSDT 2026-08-27) includes zero-trade seconds whose price is carried; they advance time but
     never touch OHLC. A minute with no trade becomes a flat bar at the carried price, as Binance does.
   - A bar is emitted only when its minute is over (second :59 closed, a later tick, or a stalled-stream close).
     The `Bar` object is created at close and is frozen. Late ticks are dropped and counted, never merged.
   - A minute counts only if the builder listened from its first instant. **Found by the first live run:** the
     scanner started at :30 and closed a 30-second "bar". The minute in progress at start or after a reconnect is
     now dropped and counted (`incomplete`).
   - `quote_volume` / `taker_buy_base` come from new optional fields of `normalize._kline` (`q`, `V`); ticks
     recorded before this change lack them and give NaN (unknown), never 0.
3. **Instant alignment** (`scanner/scanner.py`). Per symbol, `progress` = exchange time of its last tick; every
   later event of that symbol is later than its progress (capped just below a started minute whose first trade
   has not arrived). Instant `t` is released to `LoopCore` when every symbol's progress ≥ t, so all symbols'
   closes and opens at `t` enter together, as in replay. Offline this is exact.
   Live, `grace_ms` (default 3 s, exchange time, not wall clock: the recording shows receive-vs-exchange offsets of
   ~15 s on this machine) releases instants a silent symbol would otherwise hold. A late CLOSE is dropped (a gap);
   a late OPEN still fills pending paper orders at its open price, at an opens-only instant = when it became known.
4. **Paper account.** `TrendSMA` asks `ctx.position()`, so the scanner needs the same simulated position book as
   replay, or signals would differ (it would re-open forever). It holds a `PaperAccount` (mode `LIVE_PAPER`).
   Cost numbers only size paper positions; the real fee rate and spreads are UNKNOWN (T2.3).
5. **Registry** (`scanner/registry.py`): name → family, default params, version, evidence pointer (repo path),
   `gate_status` (`PENDING` until T3.3 evaluates it). `trend_sma` is the only registered plugin.
6. **Output** (`scanner/sink.py`): T6.1 envelopes, append-only. Live: `data/local/signals/<UTC date>.jsonl`,
   `mode: "LIVE_PAPER"`, `simulated: true`, `run_id: "live-<date>"`, `seq` continuing across restarts.
   Offline `--once-replay` runs the identical path but writes `mode: "REPLAY"` to
   `data/local/signals/once-replay/<run_id>.jsonl`, never into the dated live files.

## Alignment with T6.1's `signal` event (docs/loop/designs/T6.1.md §4.3), and mismatches

Matched: envelope `v, type, seq, ts_emit_ms, ts_event_ms, mode, simulated, run_id, data`; data `signal_id,
strategy_id, strategy_version, symbol, side ("LONG"), ref_price, reason, gate_status_at_fire, latency_ms.tick_to_signal`.

Mismatches, left for T5.1 to settle rather than papered over with numbers:
- `class` (TRADEABLE/OBSERVED) is non-nullable in T6.1, but it needs an expected move and a round-trip cost; both are
  UNKNOWN for `trend_sma`, so the scanner writes `null`. `cost_rt_pct` (non-nullable in T6.1) is also `null`.
- T6.1 has no `action`: exits show only as `paper_fill`/`position`. The scanner adds `action: open|close`, plus
  `interval`, `params`, `family`, `evidence`.
- `tick_to_signal` is receive→emit on the local clock (live only); offline it is `null`.

## Failure modes (pre-mortem: it is 3 months later and this failed, why?)

1. **A partial bar reached a strategy** (start-up, reconnect, dropped seconds). *Guard:* completeness rule,
   `discard_open()` on reconnect, tests for both; the stats count `incomplete` and `late`.
2. **Live and replay drifted.** *Guard:* one `LoopCore`; the equivalence tests (synthetic and recorded history)
   compare every signal, every 1m and 1d bar, every paper trade.
3. **A silent symbol froze the scanner**, or grace released instants too early and fills moved. *Guard:* grace in
   exchange time; late OPENs still fill; late CLOSEs are counted, visible in the summary.
4. **Cold start.** `trend_sma` needs 50 daily bars; the live scanner starts with none, so it emits nothing for 50
   days. Priming from history is not done here (the gap between the last history file and now would distort the SMA);
   it is a follow-up task.
5. **Someone reads a LIVE_PAPER signal as a trade.** *Guard:* `simulated: true` on every record, no order path,
   import-graph test.

## Test plan (tests/loop/test_scanner.py, written first)

Builder: closes only at minute end; zero-trade seconds and flat minutes; unclosed/duplicate/late ticks; aggTrade
sums; partial start and reconnect minutes never emitted; derived ticks rebuild the source bars exactly; real
Binance 1s klines rebuild real Binance 1m bars (skips without data). Scanner: no partial bar reaches a strategy;
an instant waits for every symbol; grace release and late-bar handling; late OPEN still fills. **Key:** replay vs
live path identical on a synthetic history and on recorded BTC/ETH history 2025-09..2026-02 (before the holdout).
Records: T6.1 envelope, LIVE_PAPER, simulated, append-only, seq continues. Registry, CLI opt-in, import graph.
