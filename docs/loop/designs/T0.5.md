# T0.5 · Design: record every real exit honestly (F3)

Status: **design only, waiting on the owner.** The trend_follower part is order code and goes in
T8.1. The report relabel (§4) is a separate task, T0.10.

## Problem

The real-money book in `scripts/trend_follower.py` **has no closed-trade record of its own.**

- `st["log"]` (`:236`) is the **paper** log. It gets an entry for every paper exit across all
  53 symbols in `SYMS`, priced at the daily candle close `px`, whether or not real money was
  involved.
- A real sell (`:271`) removes the position from `real.open` (`:272`) and writes **nothing else**:
  no fill price, no filled qty, no fee, no PnL.
- When the sellable balance is below the market minimum, the record is **deleted**
  (`:264-270`). The only trace is an `ERR` string in the Telegram message.

Meanwhile, readers present that paper log as the real book:

- `scripts/expectancy_vs_fee.py:101` labels `trend-state.json` `log` as `"trend_follower (REAL $)"`.
- `scripts/fee_audit.py:97-115` calls it "the trend book (the one holding real money)" and computes
  `gross_usd`/`net_usd` as `sum(ret) * 5.0`: a hardcoded $5 stake (the code's `SIZE_USD` is 5.5)
  applied to paper exits on symbols that were never bought with real money.

So every "real" trend number downstream is derived from the paper book. By the owner's
rule 2, that's the worst failure mode: plausible numbers that aren't true.
**This is a strong lead for work item 1 (the live-record discrepancy).** It can't be
confirmed without the E1 snapshot (compare `trend-state.json` `log` against the wallet's trade history).

## Design

### 1. A real closed record: `real.closed`
A new list in `trend-state.json`, appended **only** when a real sell is confirmed:

```json
{
  "book": "real", "symbol": "DOGE/USDT",
  "cid": "tf-DOGE-202609251600-ab12", "order_id": "123456",
  "qty": 23.0,
  "entry": 0.2412,  "entry_status": "FILL",
  "exit":  0.2388,  "exit_status":  "FILL",
  "fee_usd": 0.0053, "fee_status": "FILL",
  "pnl_usd": -0.0605,
  "reason": "trend-broke", "open_ts": "...", "close_ts": "..."
}
```

Rules:
- `qty`, `exit` and fees come from the sell order's response (`filled`, `average`, `fee`/`fees`).
- Any value the exchange didn't give us is `null` with `<field>_status: "UNKNOWN"`. There is never a
  candle price, a planned qty or a fee estimate standing in for it.
- `pnl_usd` is computed only when entry, exit and qty are all known. Otherwise it's `null`, and
  aggregators must count it as "unknown", not zero.
- Existing positions opened before this change have no fill-based entry. They carry
  `entry_status: "BOOKED"` (the value we recorded, which was the candle `px`, not a fill), so the
  difference is visible rather than laundered into `FILL`.

### 2. No silent deletion
The `:264-270` branch no longer deletes the record. It moves it to `real.closed` with
`reason: "NO_SELLABLE_BALANCE"`, `free` and `booked` quantities, and an exit resolved as follows:

1. Look up our own sells for the symbol since `open_ts` via `fetch_my_trades(symbol, since=open_ts_ms)`
   (ccxt `binance.py:8392`).
2. If sells exist whose total amount accounts for the missing quantity (`booked − free`, within one
   lot step), record their **volume-weighted** price with `exit_status: "TRADE_HISTORY"` and list
   the trade ids.
3. Otherwise `exit: null, exit_status: "UNKNOWN"`, and the alert says the exit could not be
   reconstructed. It never falls back to the current price. (That fallback is exactly the defect
   in `live_executor.py:399`, F4.)

### 3. The alert text
Real closes and paper closes are already separated in the message (`was_real`, `:244`). Real
closes will show the fill price and PnL, or the literal word `UNKNOWN`.

### 4. Readers stop calling the paper log "real" (separate PR, T0.10)
- `expectancy_vs_fee.py:101`: relabel the `log` source as `"trend_follower (paper universe)"`,
  and add a second source, `real.closed`, labelled `"trend_follower (REAL $)"`, which reads `pnl_usd`
  and skips `null` values while reporting how many were UNKNOWN.
- `fee_audit.py:97-115`: compute the "real money" block from `real.closed`, not `log`, and remove the
  hardcoded `stake = 5.0`. Until `real.closed` has entries, the block says `"no real closes recorded yet"`
  rather than printing a number.
- `book_units.py`: add a `real.closed` row (`pnl_usd`, DOLLARS, from the fill).

Reporting code isn't order code, but it changes numbers the owner reads, so this still goes
design first and in its own PR.

**Shipped 2026-10-08 (branch `loop/T0.10-real-vs-paper-labels`, PR pending owner merge).**
The writer side landed on `main` first (`trend_follower.py` `real.closed`, T8.1 partial), so the
readers were the remaining gap. `real.closed` already held one record when this shipped — a DOGE
close with `pnl_usd: null` (entry was `BOOKED`, not a fill) and `pnl_gross_usd: 0.0851` — which is
exactly the UNKNOWN case the readers must not launder into `$0.00`.

Two additions beyond the letter of §4, both required to keep the readers honest:

1. `book_units.summarise_dollars(book, records)` — a DOLLARS-book summary that counts
   `n_unknown` and returns `total_usd: None` (never `0.0`) when nothing is priced. A money total
   must never be printed without the count it could not price.
2. `book_units.as_percent("real_closed", rec)` derives the percent from the **fill prices**
   (`entry`/`exit`), never `pnl_usd / qty`. `qty` is a base-asset amount, so that division is the
   exact unit confusion the module exists to prevent (it would re-introduce error #3 from the
   docstring). Covered by a dedicated test.
3. `expectancy_vs_fee.py` is wrapped in `main()` with an `if __name__ == "__main__"` guard so its
   `real_closed_lines()` helper is importable without executing the whole report (needed by the
   tests; also stops an import from re-printing).

`fee_audit.books_from_trend()` replaces the inline block; `applied_to_books` now has two keys,
`trend_real_closed` and `trend_paper_universe`. Grep confirms nothing downstream reads the old
`trend_closed` key (only `fee_audit.py`'s own output file used it).

**Found, not fixed (own task):** `per_symbol_net.py:41` still reads `trend-state.json` `log` under
the name `trend_follower` — the same paper-as-real confusion, one level out. Filed as T0.11.

## Pre-mortem: it's 3 months later and this failed. Why?

- **The site or a report shows "$0.00 real PnL"** because the aggregator summed only `pnl_usd` values
  that were present and treated the rest as 0. Mitigation: `book_units.py` owns the reading and returns
  `(sum_known, n_unknown)`; any reader that prints a total must print `n_unknown` next to it.
- **The trade history is ambiguous** (dust plus manual trades on the same symbol). Rule 2 accepts a
  match only when the quantities reconcile within one lot step; anything else is UNKNOWN.
- **The history lookup is rate-limited or fails.** The record is still moved to `real.closed` with `UNKNOWN`
  and `exit_resolve_error`. A later run doesn't retry automatically, because a human decides whether it's worth
  it. That avoids silent churn.
- **Old positions (`BOOKED` entries) mix with new ones in stats.** `entry_status` makes them
  filterable, and the T0.10 report shows them separately.

## Test plan

For T8.1 (trend_follower part), fake exchange, no network:
1. Sell fills with `average` and `fee`: `real.closed` has FILL values and a computed `pnl_usd`.
2. Sell response missing `average`: `exit: null, exit_status: UNKNOWN, pnl_usd: null`.
3. Free below minimum and a matching sell in the history: VWAP exit with `TRADE_HISTORY` status and trade ids.
4. Free below minimum and no matching history: `exit: null, UNKNOWN`; the record isn't deleted.
5. The paper log is unchanged by any real event.

For T0.10 (readers):
6. `fee_audit` with an empty `real.closed` prints "no real closes recorded yet", not a number.
7. `expectancy_vs_fee` shows paper and real as separate rows; UNKNOWN count shown.
