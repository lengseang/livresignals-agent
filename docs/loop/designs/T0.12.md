# T0.12 — normalise the symbol key before the combined aggregation

## Problem

`per_symbol_net.py` combines trades from seven books into one per-symbol view
so a coin can be judged on its whole record. It groups by the raw
`symbol`/`pair` field. The books do not agree on the spelling:

| writer            | example key | shape            |
|-------------------|-------------|------------------|
| trend (paper+real)| `NEAR/USDT` | slash-separated  |
| unified_trader    | `NEAR/USDT` | slash-separated  |
| adaptive_engine   | `NEAR/USDT` | slash-separated  |
| regime_trader     | `NEARUSDT`  | concatenated     |

`regime_trader.py` trades Bybit **linear perpetuals** and stores the venue
symbol verbatim (`SYMS = [...]` at `:244`, `"symbol": "NEARUSDT"` in the log).
Every other book writes the base/quote form.

Effect: the same coin appears as **two rows** in ALL BOOKS COMBINED —
`NEAR/USDT` (trend/unified/adaptive) and `NEARUSDT` (regime). The combined
statistics for NEAR are split in half, so:

- its `n` is understated, so a symbol with a real edge can fall under the `n<5`
  floor and vanish from the table;
- its `t` statistic is computed on a fraction of its trades, so a genuinely
  significant edge can read `⏳ unproven` (|t|<2) only because half the sample
  was filed under a different name;
- the `books:` attribution line (`[b for b in per_book if sym in per_book[b]]`)
  is correct per row but the two rows can never be read together.

This is the same *class* of defect as T0.10/T0.11: a reader presents a
misleading picture because it trusts the field as written instead of the fact
it stands for. There the unit lied; here the name does.

## Reality check (measured, this repo)

Read directly from the state files on 2026-10-09:

```
trend-state.json   log     -> ADA/USDT, NEAR/USDT, ...      (slash)
trend-state.json   real.closed -> DOGE/USDT                  (slash)
unified-paper.json closed  -> NEAR/USDT, SOL/USDT, ...       (slash)
adaptive-state.json closed_trades -> BTC/USDT, XRP/USDT      (slash)
regime-state.json  log     -> NEARUSDT, SOLUSDT, AVAXUSDT... (no slash)
```

`regime-state.json` `log` sample record:
`{"symbol": "NEARUSDT", "side": 1, "entry": 2.297, "exit": 2.353, ...}`.
So `NEAR` and `SOL` are the two live collisions today (both also appear as
`NEAR/USDT`/`SOL/USDT` in the slash books).

## Options

1. **Relabel in the writer.** Change `regime_trader.py` to store `NEAR/USDT`.
   Rejected: it is on the loop's never-edit list (real money, Bybit demo now
   but money-shaped), and it would break every historical record already on
   disk plus the venue reconciliation that matches `rp["symbol"]` verbatim
   (`:384`, `:416`). A reader fix cannot rewrite history; the key format is a
   property of the record, not a mistake to correct in place.
2. **Normalise in the reader at the point of grouping.** One helper,
   `norm_symbol()`, applied in `per_symbol_net.main()` where `sym` is first
   read, and to the per-book keys. Display keeps the canonical form.
   Chosen.
3. **A shared `symbols.py` module used by all readers.** Right long-term, but
   scope creep for one task, and `fee_audit.py` / `expectancy_vs_fee.py` do not
   aggregate per symbol, so they do not have the bug. A function in
   `per_symbol_net.py` (next to its single caller) is the one-change-per-PR
   shape LOOP §3.3 asks for. Extract to a module when a second caller appears.

## Choice

Add `norm_symbol(key: str) -> str` to `per_symbol_net.py` and apply it wherever
a symbol key is produced in `main()`, plus in `_print_real_book()`.

`norm_symbol` rules (format, not identity guessing):

- strip surrounding whitespace;
- if the key already contains `/`, return the two sides upper-cased and
  joined with a single slash (`NEAR/USDT`, `near/usdt` -> `NEAR/USDT`);
- otherwise split a trailing known quote (`USDT`, `USDC`, `USD`, `BTC`, `ETH`,
  `EUR`) off the end and rejoin as `BASE/QUOTE` (`NEARUSDT` -> `NEAR/USDT`);
- a key that matches **no** rule is returned **UNCHANGED** and upper-cased:
  never invented into a slash form. A symbol we cannot parse is shown as it
  was written, which is the honest default (LOOP §3.2: no synthetic value).

The quote list is explicit and ordered longest-first so `USDT` is tested before
`USD`, and `USD` before nothing. It is not derived from magnitude and not from
a field name.

## Failure modes (adversarial self-review: "it is 3 months later and this failed")

- **A base asset ending in a quote word.** `BTCUSDT` -> `BTC/USDT` is right,
  but a hypothetical `USDUSDT` (a USD-margined token) would split to `USD/USDT`
  — still the correct split, since the longest quote match wins and `USDT` is
  tried first. A pair whose *base* ends in `USD`, e.g. a token symbol
  `XUSD` quoted in `USDT` (`XUSDUSDT`), splits to `XUSD/USDT`: correct,
  because `USDT` is matched at the end, not `USD`.
- **An unknown quote (e.g. `NEARTUSD`, Turkish lira).** No quote in the list
  matches the end, so the key is returned unchanged (`NEARTUSD`) rather than
  mangled into `NEAR/TUSD`-by-guess. Collisions with a slash book would then
  still split — but only for a quote we have not seen, and wrongly merging two
  *different* assets is worse than under-merging, so unchanged is the safe
  default. Add the quote when it appears, with the record that shows it.
  (Note: `AAATUSD` **does** split to `AAAT/USD`, because `USD` is on the list
  and is a real quote — that is the stated rule working, not a bug. `TUSD` is
  not on the list, so `NEARTUSD` correctly stays whole.)
- **`XAUTUSDT` (gold).** -> `XAUT/USDT`. It currently only lives in the regime
  book; normalising it does not merge it with anything, which is correct.
- **A slash key with lowercase.** `near/usdt` -> `NEAR/USDT`, so a lowercase
  writer cannot re-split the table.
- **Two different assets, same normalised form.** Impossible here: the function
  only upper-cases and inserts a separator; it never drops characters, so two
  distinct inputs cannot collide. (If a future quote rule *removed* a
  separator this would need re-checking — it does not.)
- **Whitespace / non-string keys.** Non-str returns a sentinel `"?"` via the
  caller's existing `or "?"` fallback; `norm_symbol` itself is only called on
  the string that fallback produces.

## Test plan

`tests/loop/test_symbol_normalise.py` (no network, no data reads, loads the
script by path as `test_per_symbol_split.py` does):

1. slash form is preserved and upper-cased;
2. lower-case slash form normalises;
3. `NEARUSDT` -> `NEAR/USDT`, `SOLUSDT` -> `SOL/USDT` (the two live collisions);
4. `USDT` wins over `USD` when both could match (`XUSDUSDT` -> `XUSD/USDT`);
5. an unknown quote is returned unchanged, not invented (`AAATUSD`);
6. a bare base with no quote is unchanged (`NEAR`);
7. empty string / `?` unchanged;
8. the *behavioural* assertion: feeding one `NEAR/USDT` record and one
   `NEARUSDT` record through the grouping produces **one** symbol with **two**
   trades, not two symbols (this is the regression the task exists to stop);
9. real-book per-symbol grouping in `_print_real_book` also normalises.

Plus the existing `tests/loop` suite must stay green and `compileall scripts/`
clean.

## Anti-slop notes

- Every rule cites a real record (`regime-state.json` `log` sample quoted
  above); the quote list is explicit, not inferred.
- The `n<5`/`t` consequences are stated as *why the split matters*, not as a
  claim that any symbol currently flips a verdict — I checked: today the
  regime book's six symbols are `AVAXUSDT, DOTUSDT, LTCUSDT, NEARUSDT,
  SOLUSDT, XRPUSDT`; `NEAR` and `SOL` are the only names that also occur with a
  slash. I did not assert a verdict flip I have not measured.
- No unit is inferred and no number is synthesised: unknown quote -> unchanged.
