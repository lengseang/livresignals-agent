# T0.21 · The p1 win-rate line must not argue with the p2 verdict beside it

**Status:** shipped 2026-11-11 (overnight shift). Branch work from the uncommitted
T0.21 tree state; two defects added on top of the inherited one.

## Inherited defect (already fixed in the tree, verified here)

Rule 2 of `_suggest` read `paper` — the whole collapsed book — and said, at
priority 1, every run:

    Paper win rate 42.9% below 55% — the capitulation edge may be decaying.

Measured on `reports/improvement-report.json` 2026-11-11T09:30Z: `paper.n=2999`
at 42.9%, of which **1,517 fills belong to eight edges that cannot fill** (seven
STOPPED in `signals-state.json`, plus `loose` idle since 2026-10-11). The one
live edge, `validated`, reads 45.1% over n=1482. The population fix is right and
its 7 tests are real: **7 passed with the change, 7 failed on clean `HEAD`** —
`stats_of` does not exist at `HEAD`, so the control is unambiguous.

## 🔴 Defect 1 (found this shift): the p1 line duplicates the p2 verdict

Run the fixed loop, then read what a reader sees:

```text
P1: COHORT win rate 45.2% NET on the LIVE edges (validated, n=1484) is below the
    55% bar. ... The 55% bar remains unproven on a net basis. ...
P2: Edge 'validated' DECAYING (net): 45.2% WR / 1484 trades / -3.33 net ...
    Tighten its entry (deeper dip / lower RSI) or stand it down.
```

Both paragraphs are computed from the **same 1,484 rows**, both say the edge is
decaying, both say to tighten the entry. Rule 4b already issues a per-edge
verdict on exactly those rows. When the live cohort **is** a single edge, p1 and
p2 are one finding printed twice — and the second time it is at priority 1, above
the per-edge line that has the actual numbers.

Cause: `win_rate_population` is the live split, and today the live split is one
edge. The general case is fine (a cohort of several edges needs its own line);
the n_edges==1 case is where it collapses.

## 🔴 Defect 2 (found this shift): the line says it is judging on gross, and judges on net

The comment block claims *"The verdict is therefore drawn on the book's own GROSS
rate against the gross bar."* The code two lines below it:

```python
wr_judged = wr_base.get("win_rate")     # <- NET (that is what analyze() stores)
```

and `stats_of()`'s edge-row branch writes `"win_rate_gross": None` (line 889),
because an edge row carries `gross_win`/`gross_loss` as **dollar sums** and no
gross win **count** — so a gross *rate* is genuinely not derivable from the live
population. The tests pass only because each fixture **injects**
`win_rate_gross: 56.0` by hand (`test_a_book_that_pays_its_costs_is_not_called_decaying`
line 125). The live path emits `null`, so the guard that was supposed to prevent
a net-basis false alarm never sees a gross number at all.

This is the "a module that prints numbers must not restate them in prose" family:
the prose describes a computation that does not exist.

## Choice

Do **not** invent a gross rate. Two changes:

1. **Suppress the cohort line when the cohort is one edge** — rule 4b owns it.
   Emit a `cohort == member` relationship explicitly in a comment, and pin it with
   a test: the exact live shape must produce **one** edge_decay line, not two.
2. **Make the prose say what the code does** — the line is judged on the book's
   NET rate; state that, and drop the "the bar remains unproven on a net basis"
   sentence when the verdict is itself being drawn on net (it was self-refuting:
   fire on net, then disclaim net). Keep the 2026-09-21 gross-provenance note as
   history, not as an excuse.

## Failure modes (pre-mortem: it is 3 months later and this went wrong)

- **The cohort grows to 3 edges and the p2 line goes quiet** → the p1 line must
  still fire. The suppression is `len(edges) == 1` only, and a fixture with two
  live edges must assert the p1 line exists.
- **Someone "fixes" the gross gap by deriving gross from `gross_win/gross_loss`**
  → those are dollars, not counts; a dollar ratio is a profit factor, not a win
  rate. The comment now says so, and the field stays `None`.
- **A future reader deletes the suppression as dead code** → the test that pins
  the live shape fails, and names the duplicate.

## Test plan

- live shape (one edge) → exactly one `edge_decay` line, and it is the per-edge one
- two live edges, both decaying → the cohort line **is** present
- net-positive low-WR cohort → still left alone (inherited guard, unchanged)
- the judged rate quoted == the net rate the population carries
- mutation: remove the `len(edges)==1` guard → the live-shape test goes red
