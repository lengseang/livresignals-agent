# T0.18 — a named pair must be a pair the predicate produced

**Status:** built on `loop/T0.18-redundant-pair-provenance` (from
`loop/T0.16-dead-edge-window-anchor`). Read-only research + one predicate
change in `scripts/paper_book.py` + tests. No order path touched.

## Problem

`improvement_loop` prints, at priority 3, on every live run:

> REDUNDANT — copy of another edge's handoff, no better net/WR on a
> checkable sample: breakout ~ loose; momentum ~ loose; rsi2 ~ supertrend.

The sentence is produced by `paper_book.edge_liveness`'s redundancy scan,
which calls `_shares_handoff(a, b)`: same tf, same regime, **same entry tick,
within 72h**.

Measured on the live book (2026-11-10):

| edge | last fill | n (collapsed) |
|---|---|---|
| loose | 2026-10-11 | 1261 |
| breakout | 2026-09-13 | 17 |
| momentum | 2026-09-13 | 27 |
| rsi2 | 2026-09-08 | 7 |
| supertrend | 2026-09-08 | 121 |

`breakout` (last fill 09-13) cannot be within 72h of `loose` (last fill
10-11): **28 days apart**. Same for `momentum`. Two of the three published
pairs could not have been produced by the predicate that is defined to
produce them — they had to come from a much older state of the book and are
being carried in the sentence as if they were current.

## Why this matters more than a stale string

1. The line tells the owner "do not tune the copy separately from its parent".
   A pair whose two halves never met doubles the configuration that is
   declared un-tunable, on evidence that does not exist.
2. The `rsi2` half is real: **21 of rsi2's 27 fills** share a tick with a
   `supertrend` row. So a fix that simply drops unproven pairs would be
   wrong too, and the correct fix must be able to tell the two apart.
3. It is the same class of defect the loop keeps finding: a number/sentence
   whose *provenance* is not recomputed at print time.

## What the predicate was actually matching

27 groups on the collapsed book hold 2+ rows identical on
symbol+tf+entry+tp+sl (28 extra rows). 22 of the 27 are CROSS-EDGE:
`breakout & momentum`, `rsi2 & supertrend`, `bollinger & supertrend`,
untagged & `loose`, plus same-edge pairs that the multi-tf collapse leaves
because they are further apart than its 5s window. Different rule sets do not
pick the same tick by accident: these are one decision stamped with different
labels, or one design re-entering a level it already taught exits for.

## Options

**A. Print only pairs whose two edges both filled inside the window.**
Rejected: it is a display filter over a stale decision; the underlying scan
still pairs whatever it likes, and the next sentence built on it inherits the
same problem.

**B. Require the shared handoff to be recent (both edges filled in 72h).**
Rejected for the same reason, and it would delete the `rsi2 ~ supertrend`
link (last fills 09-08 for both — it would survive) while doing nothing about
the real question: *what makes two records one signal?*

**C. Make "one signal" mean what it says: same entry tick AND the same taught
plan.** Chosen.

## Choice (C) — the predicate now

```
same tf family            (unchanged)
same regime               (unchanged)
same entry tick           (unchanged)
different taught (tp,sl)  -> NOT a pair, however close in time
|gap| > 72h               -> NOT a pair
same taught (tp,sl)       -> a pair (inside 72h)
no plan on either row     -> a pair only if |gap| <= 5s (one scan)
```

Rationale for each clause:

* **Same taught plan inside 72h = one handoff.** An entry tick plus the same
  TP *and* SL is the announce-and-teach pair. Measured: 22 of the 27 groups
  are cross-edge and several are a day or more apart.
* **Different plan = not one handoff.** Two designs can meet a support level
  hours apart with deliberately different exits; calling that a copy is the
  same mistake in the other direction. (Today no live pair is in this shape —
  see mutations M3.)
* **No plan = silent, fall back to the scan window.** An absent TP/SL must not
  read as a match (that would pair every plan-less row with every other) and
  must not read as a mismatch. The 5s window is the same bound the multi-tf
  collapse uses for "one scan"; the old 72h-with-no-evidence is what let two
  designs that met a day apart at one price read as copies.

## Failure modes / adversarial review ("3 months later, this failed: why?")

* **The plan field stops being written.** Then every pair falls back to the
  5s rule and `rsi2 ~ supertrend` stops being named. This is why the clause
  docstring says the rsi2 link is exactly this shape and to widen the check
  before assuming the note is still true. The direction of failure is
  "fewer claims", which is the safe direction for a no-tune instruction.
* **The same design re-enters a level it already taught exits for, minutes
  later.** It pairs with its own earlier row (same edge). `redundant` is
  keyed by edge name, so a self-pair cannot be entered (`other == e` is
  skipped). If two *different* designs genuinely re-use a level hours later
  with the same taught plan, they are still claimed as one handoff — that is
  the intended reading, not an accident.
* **`regime` is None on most rows** (measured: 817 of 2958 collapsed rows
  carry a regime), so the regime clause compares None to None for most pairs
  and blocks nothing. Unchanged from before; not widened here.
* **The sentence is now shorter.** An owner who read `breakout ~ loose`
  yesterday will see it disappear. That is the point, but the journal must
  say it so the vanishing is not read as "the copy was fixed".

## Test plan (shipped)

`tests/loop/test_redundant_pair_provenance.py`, 14 tests:

* predicate: same plan 24h apart → pair; different plan 2h apart → not;
  no plan 2s apart → pair; no plan 2h apart → not; 4 days apart → not;
  cross-tf with the same plan → not; regime mismatch → not; tp equal / sl
  different → not (the plan is compared as a pair).
* sentence: a pair the predicate rejects is never named (the observed
  defect, rebuilt as a fixture); an accepted pair still is (not a mute
  button); the parent is not printed as a pair.
* **real path, real book:** `improvement_loop.analyze()` re-derives
  `edge_meta["redundant"]` and every edge named in the REDUNDANT sentence
  must equal what `edge_liveness` computes on `data/unified-paper.json`.

Mutations: 8 applied, 7 caught; the survivor (M3, "different plan allowed
again") is documented in the test it was supposed to fail — the end-to-end
fixture cannot see it because the copy's per-fill return then exceeds the
parent's, so the independent "adds nothing" test refuses it anyway. The
predicate-level test does catch the other direction (M7, tp-only compare).
